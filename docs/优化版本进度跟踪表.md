# 优化版本进度跟踪表

更新时间：2026-05-18

本文档用于跟踪 `finance-agent` 从“基础可用”走向“私人金融助手长期运行”的优化版本任务。这里不重复记录已经完成的数据表、基础推荐链路和 CLI/MCP 入口，只跟踪当前尚未完成的 9 条主线。

## 1. 总体路线

| 阶段 | 目标 | 当前状态 | 验收标准 |
| --- | --- | --- | --- |
| V1.1 | 让 Hermes 能稳定调用金融工具 | 待开始 | Hermes/Skill 能通过 CLI 或 MCP 调用 Workflow、工具、报告和审计查询 |
| V1.2 | 让系统能被行情和风险事件自动唤起 | 基础版已完成 | 持仓波动、观察池触发条件、风险事件能唤醒 Hermes-Agent 或内部金融 Agent |
| V1.3 | 接入真实模型分析和高风险复核 | 待开始 | DeepSeek V4 Pro / GPT-5.5 Pro 能按路由协议输出结构化结论并回写审计 |
| V1.4 | 把持仓和观察池 Workflow 升级为圆桌 | 基础版已完成 | `portfolio_monitoring`、`watchlist_management` 具备工具调用、圆桌观点、报告和复核 |
| V1.5 | 数据层生产化和因子增强 | 待开始 | 批量刷新、缺口补采、交易日历、限流、完整因子窗口可稳定运行 |
| V2.0 | 私人金融助手体验闭环 | 待开始 | 前端、长期记忆、人工确认、复盘和操作反馈形成闭环 |

## 3. O1 Hermes 真正接入

| 子任务 | 状态 | 说明 |
| --- | --- | --- |
| 编写金融助手 Skill 使用规范 | 待开始 | 说明 Hermes 什么时候调用 `workflows run`、什么时候查询工具、什么时候只读报告 |
| 配置 Hermes 调用 CLI | 待开始 | CLI 适合本地开发、批处理和直接命令调用 |
| 配置 Hermes 调用 MCP | 待开始 | MCP 适合正式长期 Agent 工具入口 |
| 明确工具权限边界 | 待开始 | 禁止 Hermes 直接联网查行情，必须消费本项目已入库事实 |
| 增加 Hermes 冒烟脚本 | 待开始 | 验证 Hermes 能列出 Workflow、运行分析、读取报告 |

验收标准：

- Hermes 能发现 `list_workflows`、`run_workflow`、`get_report`、`call_tool`。
- Hermes 能基于用户问题选择合适 Workflow。
- Hermes 的输出能引用 Workflow 报告和审计事件，而不是自己凭空给结论。

| 数据质量触发规则 | 已完成基础版 | 已支持 `data_quality_degraded`，读取 `data_quality_snapshots` 并唤醒 Agent 复核 |

- 每个触发都有 `trigger_type`、`trigger_ref`、`dedup_key` 和 `assistant_trigger_events` 审计。
- 高频数据变化通过冷却窗口抑制重复触发。

| CLI 入口 | 已完成基础版 | 已新增 `finance-agent agent run-once` 和 `finance-agent agent run-task` |
| 冒烟验证 | 已完成 | `smoke_internal_agent_loop.py` 已验证直接 runner 和 CLI 均能消费触发事件、调用 Workflow 并避免重复执行 |
| 模型接入预留 | 已完成基础版 | 当前使用确定性 planner；后续在同一边界内接 DeepSeek V4 Pro 和 GPT-5.5 Pro 复核协议 |

验收标准：

- 模型输出必须能解析为结构化 JSON。
- 高风险动作必须经过复核策略。
- 模型不可用时不能阻断基础监控，只能降低置信度或标记待复核。

- `smoke_portfolio_watchlist_roundtable_workflows.py` 已验证两个 Workflow 均输出 `node_trace`、`tool_calls`、`roundtable_opinions`、`model_routes`、`high_risk_reviews`、`report`。
- 旧的 `smoke_portfolio_monitoring_workflow.py` 和 `smoke_watchlist_management_workflow.py` 仍通过，说明规则版闭环未被破坏。
