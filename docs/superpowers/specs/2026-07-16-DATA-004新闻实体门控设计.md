# DATA-004 新闻实体门控设计

**状态：** 已批准

**批准日期：** 2026-07-16

**目标：** 将东方财富通用关键词新闻搜索改为“代码＋规范公司名”查询，并在归一化前执行可审计的实体相关性门控；无法证明属于目标股票的新闻只保留原始报文，不进入活动事件、证据和评分。

## 1. 已确认根因

1. AKShare `stock_news_em` 调用的是通用新闻关键词搜索，不是结构化个股新闻接口。
2. 返回表中的“关键词”是客户端回填的请求值，不是源端实体标识。
3. `AshareP1Collector.collect_stock_news` 已取得 `asset_name`，但只把股票代码传给 Provider。
4. `AshareEventProvider.fetch_stock_news` 使用代码搜索，并把全部结果交给归一化层。
5. `normalize_ashare_stock_news` 无条件把全部行绑定为请求股票的 `asset_id`。
6. 数据库中至少 22 条、7 个资产存在可严格证明的同代码实体碰撞；`000685` 中山公用被绑定了 7 条上证科创板芯片指数新闻。

## 2. 已批准决策

1. 查询关键词改为“六位股票代码＋规范公司名”。
2. 无法证明与目标股票相关的结果 fail-closed。
3. 被拒绝结果完整保留在 `raw_records`，但不生成活动事件、证据或事件因子。
4. 历史错误新闻不物理删除，采用隔离标记；活动查询和评分排除隔离记录。

## 3. 数据流

```text
Collector(symbol, asset_name)
  -> Provider(query="代码 公司名")
  -> 原始 DataFrame
  -> 实体门控逐行判定
       -> passed：生成 EventRecordData + EvidenceData
       -> failed/ambiguous：写过滤审计，不生成事件和证据
  -> archive_provider_result 始终归档完整审计
  -> 只有 passed 行进入事件仓储
```

公告 `stock_notice_report` 不经过该关键词门控，保持原有结构化公告逻辑。

## 4. 查询契约

- Collector 必须把数据库中的规范 `asset_name` 传给 Provider。
- Provider 必须同时接收 `symbol` 和 `asset_name`，查询字符串为去除交易所前缀后的六位代码、一个空格和规范公司名。
- `asset_name` 缺失、为空或仍等于股票代码时，Provider 返回 `unavailable`，原因 `missing_asset_name`；禁止退回纯代码搜索。
- 请求参数、实际查询字符串和规则版本写入 Provider payload。
- 每次最多保留源端返回的原始行数量、通过数量、拒绝数量和逐原因统计。

## 5. 名称与代码规范化

实体门控使用确定性规则，不调用模型：

1. 统一全角/半角、大小写和空白。
2. 保留规范公司名原文，同时生成审计用核心简称。
3. 核心简称只移除公司法律形态后缀，例如“股份有限公司”“有限责任公司”和“集团股份有限公司”。
4. `ST`、`*ST`、`N`、`C` 等证券状态前缀只在规范公司名本身含有时生成对应别名，不能任意猜测品牌名。
5. 长度不足 2 个汉字或属于通用词的别名不作为单独通过依据。
6. 股票代码按主板规则推导预期交易所：`000/001/002/003` 为深市，`600/601/603/605` 为沪市。

不维护人工品牌别名表；新增别名必须来自可追溯资产身份数据并单独版本化。

## 6. 逐行实体判定

判定文本由标题和摘要组成，正文补抓不参与首次实体判定，避免先写错事件再补正文。

### 6.1 通过条件

满足以下任一条件且不存在冲突证据时，状态为 `passed`：

- 文本包含规范公司名；
- 文本包含通过规则生成且不属于通用词的核心简称；
- 文本包含六位代码和与目标股票一致的交易所后缀，例如目标为深市 `000685` 时出现 `000685.SZ`。

### 6.2 拒绝条件

以下任一条件成立即为 `failed`：

- 文本包含同代码但交易所后缀冲突，例如目标为深市股票却出现 `000685.SH`；
- 文本明确把同代码描述为指数、ETF 跟踪标的或其他非目标证券，且没有规范公司名；
- 文本出现另一个明确公司实体，且没有目标公司名或匹配交易所代码；
- 标题和摘要均为空。

### 6.3 歧义条件

只有以下弱证据时状态为 `ambiguous`，处理结果与 `failed` 相同：

- 只出现无交易所后缀的六位代码；
- 只出现源端回填的“关键词”列；
- 查询返回行没有公司名、可靠简称或匹配交易所代码。

`failed` 与 `ambiguous` 都不得生成事件和证据，但必须分别统计。

## 7. 原始报文与过滤审计

Provider payload 增加 `entity_validation`：

```json
{
  "rule_version": "ashare_news_entity_v1",
  "query": "000685 中山公用",
  "asset_name": "中山公用",
  "source_row_count": 10,
  "passed_count": 8,
  "failed_count": 1,
  "ambiguous_count": 1,
  "filtered_rows": [
    {
      "row_index": 3,
      "status": "failed",
      "reason": "conflicting_exchange_suffix",
      "raw": {}
    }
  ]
}
```

`filtered_rows[*].raw` 保存原始行，不做不可逆裁剪。日志只输出计数和原因，不重复打印完整正文。

当源端有行但全部被拒绝时，Provider 状态为 `unavailable`，并保留 `source_row_count > 0` 和过滤明细，不能伪装为“源端无新闻”。

## 8. 新事件与证据契约

只有 `passed` 行生成事件和证据：

- 事件 payload 写入 `entity_validation.status=passed`、规则版本、匹配依据和规范公司名。
- 证据 payload 写入相同验证状态，并通过 `data_ref` 指向事件。
- `event_id` 继续使用源、目标股票、标题和发布时间生成，保持已通过事件幂等。
- 过滤行不创建资产、不创建事件、不创建证据，也不进入正文补抓队列。
- 事件因子只消费验证通过的关键词新闻；公告等结构化事件不受影响。

## 9. 历史记录隔离

新增一次性历史重验命令，支持 `--dry-run` 和显式 `--apply`：

1. 仅扫描 `source='akshare:stock_news_em'` 的新闻事件。
2. 从 `assets` 读取规范公司名，使用同一版本规则重验标题和摘要。
3. `passed` 行写入 `payload.entity_validation.status=passed`。
4. `failed` 或 `ambiguous` 行写入对应状态、原因、规则版本和重验时间。
5. 关联 evidence 写入相同状态，不删除物理行。
6. 缺少公司名或原始文本时按 `ambiguous` 隔离。

活动查询规则：

- 非 `akshare:stock_news_em` 事件保持原行为；
- `akshare:stock_news_em` 新闻只有 `entity_validation.status=passed` 才能出现在最近事件、Agent 上下文、事件因子和活动证据中；
- 缺少验证字段的旧关键词新闻按 fail-closed 排除；
- 审计查询可显式包含隔离记录，但必须返回隔离状态。

## 10. 调度控制

- 2026-07-16 门控上线前曾暂停 `ashare.events`；历史 apply 前又临时暂停 `ashare.events.full`，在途批次均自然完成，没有强制中断或删除审计行。
- 固定样本和 200 标的真实周期已完成：200 个查询全部带规范公司名，1,822 行通过写入、38 行歧义只保留 raw，新增活动事件全部为 `passed`。
- `ashare.events` 和 `ashare.events.full` 均已恢复；恢复后调度器 `healthy=true`、心跳小于 300 秒、`last_error=null`，其他行情、资金流和正文任务继续运行。
- 连续一周证据满足前 DATA-004 保持 `执行中 / 75%`，不得标记 100%。
- 若门控异常导致全部资产均被过滤，任务保持可观测的 `partial/unavailable`，不得自动降级到纯代码搜索。

## 11. TDD 验收样本

至少覆盖以下自动化测试：

1. Provider 使用“代码＋公司名”调用 `stock_news_em`。
2. 缺失公司名时不调用纯代码搜索。
3. `000685.SH` 芯片指数新闻对中山公用返回 `failed`，事件和证据均为 0。
4. 标题包含“中山公用”的新闻返回 `passed`。
5. `000685.SZ` 且无冲突实体时可以返回 `passed`。
6. 只出现 `000685` 的新闻返回 `ambiguous`。
7. 被过滤原始行和原因完整进入 raw archive。
8. 全部过滤时 Provider 为 `unavailable`，但 `source_row_count` 保留真实数量。
9. Collector 只持久化 passed 事件和证据。
10. 历史重验 dry-run 不修改数据库，apply 幂等。
11. 活动最近事件和因子查询排除 failed、ambiguous 和未验证旧关键词新闻。
12. 公告和其他结构化事件查询不受关键词门控影响。

## 12. 真实验收

实现后执行以下真实验证：

1. 对 `000685` 中山公用分别记录旧纯代码查询和新组合查询的前 10 条结果。
2. 对已知 7 个碰撞资产重跑，错实体新增事件数必须为 0。
3. 对至少 20 个正常重点池资产采集，确认相关公司新闻仍可通过。
4. 运行历史重验 dry-run，记录 passed、failed、ambiguous 和缺少公司名数量。
5. 经审计后执行 apply，确认活动事件查询不再返回已知 22 条碰撞记录。
6. 重算受影响事件因子，确认隔离新闻不进入新因子和评分。
7. 恢复 `ashare.events`，观察至少一个真实周期，调度器保持 healthy 且 `last_error=null`。

## 13. 回滚

- 回滚代码前再次暂停 `ashare.events`，避免恢复纯代码搜索。
- 历史隔离只修改 JSON payload，不删除记录；回滚查询规则后数据仍可审计。
- 不自动移除 `entity_validation` 标记。
- 只有修复版本重新通过固定样本和真实采集验收后，才允许恢复新闻事件调度。
