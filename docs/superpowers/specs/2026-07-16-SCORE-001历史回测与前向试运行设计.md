# SCORE-001 历史回测与前向试运行设计

**状态：** 已批准

**批准日期：** 2026-07-16

**目标：** 使用严格无前视的历史 walk-forward 回测筛选短线、题材和混合策略；历史证据达标后允许进入受控试运行，并在前向验证失败时自动关闭新增试运行策略。

## 1. 已批准决策

1. 历史回测达到本文门槛后，策略可以直接进入 `trial`，不必等待前向样本先成熟。
2. 前向验证失败后，系统自动把新增试运行策略改为 `disabled`，停止生成该策略的新推荐。
3. 历史和前向收益均扣除 `0.30%` 双边交易成本与滑点。
4. 缺少当时可见的数据时返回 `insufficient_data`，禁止使用当前因子、当前成员关系或当前基本面回填历史。

## 2. 当前事实与边界

- A 股 `1d` K 线覆盖 2016-06-07 至 2026-07-16，共约 690 万条、3,207 个资产。
- `factor_frames` 只从 2026-04-27 开始，`asset_scores` 只从 2026-05-19 开始，不能代表十年历史截面。
- 当前候选池和板块成员关系主要从 2026 年 7 月开始，不能倒填为过去的成分关系。
- 现有 `DatabaseBacktestScoreSource.list_replayed_scores` 是“当前权重回放的近似截面”，不能用于生产启用结论。
- GitNexus 对 `run_factor_score_topn_backtest` 的上游影响为 HIGH，涉及调度器 `execute_job` 和 CLI `dispatch`。新实现必须使用独立研究管线，不修改该高风险核心函数。

## 3. 策略集合

每日收盘保存以下三套完整评分截面：

| 策略 ID | 说明 |
| --- | --- |
| `strategy:ashare:short_swing` | 现有短线波段策略，继续作为生产基线和比较对象 |
| `strategy:ashare:theme_momentum` | 现有题材动量策略，只有通过历史门槛才进入试运行 |
| `strategy:ashare:short_theme_mixed_v1` | 新增固定混合策略，只有通过历史门槛才进入试运行 |

混合策略使用短线和题材权重的算术平均，不在测试集上调参：

| 因子组 | 权重 |
| --- | ---: |
| `technical` | 0.270 |
| `capital_flow` | 0.200 |
| `sector_strength` | 0.130 |
| `leadership` | 0.120 |
| `event` | 0.070 |
| `fundamental` | 0.065 |
| `liquidity` | 0.065 |
| `valuation` | 0.050 |
| `risk` | 0.020 |
| `event_decay` | 0.010 |

缺失惩罚固定为每个完全缺失组 `3.5` 分、每个部分缺失组 `1.5` 分。策略 ID 带版本号；权重变化必须创建新版本，不能修改旧结果。

## 4. 无前视历史 walk-forward

### 4.1 时间语义

每个历史交易日按以下顺序执行：

1. 只读取该交易日收盘时已经可见的数据。
2. 使用截至当日的 K 线计算技术指标；不得读取下一根 K 线。
3. 只有具备可靠披露时间或采集时间且不晚于截面时间的数据，才允许进入基本面、资金流、事件和题材因子。
4. 当日收盘生成排名，下一交易日开盘作为模拟入场价。
5. 分别使用第 5、10、20 个后续交易日收盘价作为退出价。
6. 计算组合收益、候选池等权基准收益和净超额收益，再扣除 `0.30%` 成本。

历史候选池必须根据当日已有 K 线、主板代码规则、上市状态和最小预热长度重建。当前 `asset_universe_members` 不得向过去回填。

### 4.2 数据可用性门控

每个截面计算“可证明当时可见的因子权重覆盖率”。满足以下条件才进入统计：

- 至少 90% 的候选标的可用权重覆盖率不低于 80%；
- 技术指标至少具备 120 个历史交易日预热；
- 题材和领导力因子必须有该日有效的成员关系，当前成员快照不能替代；
- 基本面必须有可靠披露时间，只有报告期但没有披露时间的数据禁止使用；
- 新闻只允许使用通过 DATA-004 实体门控且发布时间不晚于截面时间的事件。

任一策略达不到覆盖要求时，该策略本次结果为 `insufficient_data`。其他策略继续独立评估，不互相借用数据。

### 4.3 历史通过门槛

每个策略独立判断。历史结果必须同时满足：

1. 总有效调仓截面不少于 120 个，三个不重叠时间阶段各不少于 30 个。
2. T+10 净超额收益的按交易日区块自助法 95% 置信区间下界大于 0。
3. 三个时间阶段中至少两个阶段的 T+10 净超额收益为正。
4. T+5 与 T+20 的整体净超额收益不能同时小于等于 0。
5. 策略组合最大回撤不能比候选池基准多 5 个百分点以上。
6. 所有成交必须使用下一交易日开盘价，所有标签必须来自截面之后。

任一条件不满足即为 `failed`；数据不足与策略失败必须分开记录。

## 5. 前向观察账本

### 5.1 追加而非重置

每日任务执行两类动作：

1. 为当日短线、题材和混合策略追加新的 `asset_scores` 物理截面；同一交易日、策略版本和因子帧保持幂等，不覆盖其他交易日。
2. 为以前到期的观察仓位补写 T+5、T+10 或 T+20 结果；未到期结果保持 `pending`。

全截面继续保存在 `asset_scores`。前向观察只为每套策略 Top 20 和同期基准保存结构化仓位与收益，不复制全市场分数。

### 5.2 新增持久化对象

| 对象 | 关键字段 | 作用 |
| --- | --- | --- |
| `strategy_observation_runs` | `observation_id`、`trade_date`、`universe_id`、数据水位、状态 | 每个交易日的不可变观察批次头 |
| `strategy_observation_positions` | `observation_id`、`strategy_id`、`asset_id`、`rank`、`score_id`、入场日与入场价 | 保存三套策略各自 Top 20 |
| `strategy_observation_outcomes` | 仓位、周期、到期交易日、毛收益、净收益、基准收益、超额收益、状态 | 保存 5/10/20 日到期结果 |
| `strategy_trial_states` | `strategy_id`、`strategy_version`、状态、历史证据 ID、前向统计、关闭原因 | 控制试运行状态机 |

唯一键必须包含交易日和策略版本，重复调度只能幂等更新同一批次，不能删除或覆盖旧批次。

## 6. 试运行状态机

```text
research -> historical_passed -> trial -> validated
                                  |
                                  -> disabled
```

- `research`：只计算研究结果，不生成新增策略推荐。
- `historical_passed`：历史门槛全部通过，保存证据和数据版本。
- `trial`：题材或混合策略开始生成独立试运行推荐。
- `validated`：前向样本达到长期门槛，保留正式可用状态。
- `disabled`：停止生成新推荐；历史评分、推荐和验证证据保留审计。

现有短线生产基线继续运行。短线策略也参加相同验证，但其失败只产生明确告警，不在没有替代基线时自动中断现有推荐链。

试运行推荐必须标记 `trial=true` 和验证证据 ID。试运行不创建自动成交；订单草案及外部执行仍需用户确认。

## 7. 前向关闭与晋级规则

每周固定评估一次，避免单个交易日噪声触发开关。

### 7.1 自动关闭

满足最少 30 个已成熟 T+10 截面和 20 个已成熟 T+20 截面后，若连续两次周度评估同时满足以下条件，则从 `trial` 改为 `disabled`：

- T+10 净超额收益中位数小于等于 0；
- T+5、T+10、T+20 中至少两个周期的净超额收益小于等于 0。

以下数据完整性问题不等待最少样本，立即关闭：

- 发现前视数据进入特征；
- 策略版本与评分版本不一致；
- 推荐引用了其他策略评分；
- 观察批次被覆盖、到期日计算错误或收益标签来自错误交易日。

试运行最大回撤比基准多 10 个百分点以上时立即关闭并创建高风险复核记录。

### 7.2 晋级

至少 60 个 T+20 截面成熟，并重新满足历史通过门槛中的收益、分阶段和回撤条件后，`trial` 才能改为 `validated`。

## 8. 历史结果持久化

历史 walk-forward 摘要复用现有 `backtest_results`：

- `strategy_id` 保存精确策略版本；
- `status` 使用 `available`、`failed` 或 `insufficient_data`；
- `metrics` 保存三个周期收益、置信区间、分阶段结果、胜率和回撤；
- `data_versions` 保存 K 线、成员关系、基本面、资金流、事件水位及代码提交；
- `payload` 保存覆盖率、排除原因、交易成本和可复现实验参数。

不得覆盖旧回测结果；`backtest_id` 必须包含策略版本、参数摘要和数据水位摘要。

## 9. 调度与故障处理

- 历史研究为显式任务，不与现有 HIGH 风险回测核心函数共用实现。
- 每日收盘任务在最终日 K 完成后追加三套截面和观察仓位。
- 每日维护任务结算所有到期结果，失败时保留 `pending` 并可幂等重试。
- 每周验证任务更新状态机；状态变更必须写审计事件。
- 任一策略失败不阻断其他策略，也不阻断基础行情采集。
- 数据不足必须显示缺失来源、权重覆盖和最早可重试日期。

## 10. 验收与测试

必须通过以下验证：

1. 使用含未来极值的固定 K 线样本，证明截面特征不读取未来行。
2. 信号在 T 日收盘产生，入场严格使用 T+1 开盘。
3. 5/10/20 日按交易日历计算，不按自然日计算。
4. 缺少历史题材成员时返回 `insufficient_data`，不能读取当前成员。
5. 每日重复执行不会新增重复批次，也不会覆盖前日批次。
6. 历史通过可使新增策略进入 `trial`；历史失败和数据不足均不能进入。
7. 前向失败连续两次后自动关闭；单次失败不关闭。
8. 已关闭策略停止生成新推荐，但历史证据仍可查询。
9. 推荐、评分和策略版本引用错配为 0。
10. 真实数据库历史研究输出数据覆盖、排除原因、三个阶段和三个周期的完整统计。

## 11. 发布与回滚

1. 先应用数据库迁移并保持所有新策略为 `research`。
2. 运行历史研究；只有真实通过的策略进入 `trial`。
3. 启用每日追加和到期结算任务，验证两个交易日不覆盖。
4. 前向状态机运行期间保持现有短线基线。
5. 回滚时先停新增观察任务，再把题材和混合状态改为 `disabled`；历史表和回测证据不删除。
