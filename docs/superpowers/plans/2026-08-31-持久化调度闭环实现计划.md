# 持久化调度闭环实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。本计划因当前分支存在必须保留的未提交调度与恢复实现，按用户确认在原工作区执行，不新建 worktree。

**目标：** 将 finance-agent 的计划、准入、排队、领取、恢复与展示统一到 PostgreSQL 持久化闭环，消除仅 1～2 个任务运行、重启丢失依赖、恢复草稿误冻结和 Web 伪 waiting 等问题。

**架构：** `BaseDataScheduler` 保留兼容入口，内部通过 `SchedulerPlanner` 形成持久化逻辑运行，通过 `SchedulerAdmissionController` 生成可审计准入状态，再由 `PersistentSchedulerWorker` 从数据库领取执行；`SchedulerRuntimeReporter` 为状态文件和 API/Web 提供同一快照。PostgreSQL 是任务状态事实来源，Redis 只保存任务内部进度，配置文件摘要用于检测 API 与 scheduler 漂移。

**技术栈：** Python 3.11、SQLAlchemy 2、PostgreSQL/TimescaleDB、Redis、FastAPI、React/TypeScript、Docker Compose、pytest、Vitest、Alembic、GitNexus。
