# 持仓监控最小闭环实现计划

> **面向 AI 代理的工作者：** 使用 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框语法来跟踪进度。

**目标：** 在 M2 数据库和应用服务地基之上，跑通第一条真实私人金融助手闭环：读取持仓，生成监控提醒，调用 `portfolio_monitoring` 工作流，输出持有/观察/减仓等结构化建议，并写入 Workflow 审计、决策日志、Finance Memory 和复盘任务。

**架构：** 第一版使用确定性规则工作流，不调用 LLM。后续再把工作流节点替换为 LangGraph / LLM Agent。服务层负责编排，工作流只消费结构化持仓、信号、风险和记忆上下文，不直接抓行情、不计算因子。

> 2026-05-19 更新：本文是已执行历史计划。知识图谱长期方案已调整为 GraphStore 配置二选一：默认 Neo4j / DozerDB，可选 Apache AGE；`financial_memory_edges` 仅作为历史兼容表保留。

**技术栈：** Python dataclass、SQLAlchemy 2.x 仓储、M2 应用服务、PostgreSQL + TimescaleDB 冒烟验证。

## 任务 2：规则版 PortfolioMonitoringWorkflow

**文件：**
- 修改：`src/finance_agent/agents/workflows/portfolio_monitoring.py`

- [x] **步骤 1：实现信号读取规则**

规则：

- bullish 且持仓盈利：默认 `hold`，提示观察加仓条件。
- bearish 或 high/critical 风险：默认 `reduce`。
- neutral/mixed：默认 `hold` 或 `watch`。

- [x] **步骤 2：实现风险反驳文本**

输出中文反方观点，至少包含信号不一致、风险发现、记忆中的历史注意事项。

- [x] **步骤 3：实现复盘问题**

每个决策输出 2-3 个下次复盘问题。
