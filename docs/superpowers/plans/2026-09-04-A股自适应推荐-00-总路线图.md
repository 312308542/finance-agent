# A 股自适应推荐总路线图实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 按四个可独立验收的阶段，把现有 A 股研究候选榜单升级为具备点时一致性、结构与板块门控、推荐生命周期、盘中持仓监控和严格上线验证的系统。

**架构：** 第一阶段建立可靠的实时行情与分钟线事实层；第二阶段构建收盘决策快照和推荐生命周期；第三阶段接入盘中持仓监控与用户界面；第四阶段用无前视 walk-forward 和前向结果控制策略上线。阶段之间只通过数据库事实和小接口通信，每个阶段完成后均可独立部署和回退。

**技术栈：** Python 3.12、FastAPI、SQLAlchemy 2、Alembic、PostgreSQL/TimescaleDB、Redis、Go/GoTDX、React 19、TypeScript、Vite、Docker Compose、pytest、Node 视图测试、Playwright、GitNexus WSL CLI。


## 阶段验收关卡

- [ ] **关卡 1：实时事实层**

  持仓 10 只热连接 P95 不超过 1 秒，重点池 50 只 P95 不超过 5 秒；连续 120 分钟测试丢失率低于 0.1%，闭合 1 分钟 K 完整率至少 99.9%，GoTDX 不再因超过单批上限返回 HTTP 400。

- [ ] **关卡 2：收盘推荐层**

  全部候选使用同一 `decision_snapshot_id`，前 20 名主结构覆盖率至少 95%，部分或过期数据不能产生 `buy_ready`，结果允许零买入，推荐连续状态和换股缓冲可通过固定样本重放。

- [ ] **关卡 3：持仓监控层**

  登记持仓后自动进入监控；结构失效、板块退潮、急跌、资金突变、T+1 和不可成交状态均有确定性测试；无变化时不重复告警，页面能区分建议与已执行事实。

- [ ] **关卡 4：策略上线层**

  点时违规为 0，至少 120 个有效截面，5/10/20 日净收益、超额、IC、分阶段表现、回撤、换手和不可成交率全部入库；未达门槛策略不能新增买入，60 个成熟 20 日前向结果后才允许进入 `validated`。

- [ ] **最终部署关卡**

  后端全量 pytest、六组前端 Node 测试、TypeScript/Vite 构建、Ruff、PyCharm 构建和 Playwright 桌面/移动端检查全部通过。Docker Compose 中迁移、API、Scheduler、Web、GoTDX、PostgreSQL、Redis 和持仓监控进程状态正常；关键接口无 HTTP 5xx、浏览器无控制台错误、PostgreSQL 无 `idle in transaction`。

## 回退策略

- 数据库迁移保持向后兼容；旧推荐表只读接口在四个阶段内持续可用。
- 每个新模块使用独立配置开关：`realtime_history_enabled`、`adaptive_recommendation_enabled`、`position_monitor_enabled`、`strict_validation_gate_enabled`。
- 关闭开关后只能回退到研究候选展示，不得回退到未经验证的自动 `buy_candidate`。
- 任何阶段的失败都保留已写入的追加事实和审计事件，不删除用户的持仓、执行登记或历史推荐。
