# A 股盘中持仓监控与页面实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 对用户已经登记的 A 股持仓持续监控结构、板块、资金、风险和交易可执行性，输出可审计的持有、禁止加仓、观察、减仓、退出或暂不可执行建议。

**架构：** `PositionMonitoringEngine` 是纯决策模块，只消费持仓监控状态和统一盘中快照；独立监控进程从第一阶段事实层读取持仓股最新行情和闭合分钟 K。状态仓储保存当前监控状态和追加事件，现有触发器只负责去重、派发和唤醒，不在触发层重写交易规则。

**技术栈：** Python 3.12、SQLAlchemy 2、Alembic、PostgreSQL、Redis、FastAPI、React 19、TypeScript、Docker Compose、pytest、Node 视图测试、Playwright。

```python
PositionActionName = Literal["hold", "add_blocked", "watch", "reduce", "exit", "unexecutable"]


@dataclass(frozen=True)
class PositionAction:
    position_id: str
    action: PositionActionName
    intended_action: PositionActionName | None
    severity: Literal["low", "medium", "high", "critical"]
    reason_codes: tuple[str, ...]
    protective_price: Decimal | None
    suggested_quantity: Decimal
    evaluated_at: datetime
    quote_snapshot_id: str
    decision_snapshot_id: str | None


class PositionMonitoringEngine:

        """按固定优先级计算单个持仓动作。"""
```

规则优先级固定为：数据不可执行 → 停牌/跌停/T+1 → 重大风险 → 结构失效 → 保护位 → 板块退潮 → 资金与量价转弱 → 加速止盈 → 正常持有。高优先级规则覆盖最低持有期，普通排名变化不参与本模块。
