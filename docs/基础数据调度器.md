# 基础数据调度器

基础数据调度器用于按频率编排 A 股和数字货币基础数据采集。它只复用现有
`scripts/data/collect_base_data.py` 采集入口，不做自动交易、评分、因子计算或 Agent
分析。

在私人金融助手架构中，基础数据调度器是上层 `PersonalFinanceAgent` 的事实输入前置层。它不直接生成买卖建议，但会为后续持仓监控、观察池触发、风险提醒和每日复盘提供最新数据。

推荐链路中的位置：

```text
基础数据调度器
 -> raw_records / market_bars / fundamental_snapshots / capital_flow_snapshots / event_records / risk_findings
 -> 因子/信号/风险更新
 -> AlertService 触发判断
 -> PersonalFinanceAgent 调度金融团队 Workflow
```

## 运行方式

打印当前计划，不触发采集：

```powershell
python scripts/data/run_base_data_scheduler.py --print-plan
```

输出内置配置模板：

```powershell
python scripts/data/run_base_data_scheduler.py --dump-default-config
```

按配置执行启用任务后退出，适合验证和后续任务编排：

```powershell
python scripts/data/run_base_data_scheduler.py --run-once
```

演练一轮启用任务，只打印将要传给采集入口的参数：

```powershell
python scripts/data/run_base_data_scheduler.py --run-once --dry-run
```

按频率常驻循环运行：

```powershell
python scripts/data/run_base_data_scheduler.py --loop
```

验证 loop 调度逻辑时可以限制周期数：

```powershell
python scripts/data/run_base_data_scheduler.py --loop --dry-run --max-cycles 1
```

## 配置结构

调度器支持 JSON 配置文件，未提供 `--config` 时使用内置默认配置。可以先导出模板：

```powershell
python scripts/data/run_base_data_scheduler.py --dump-default-config > base_data_scheduler.json
```

配置文件读取兼容普通 UTF-8 和带 BOM 的 UTF-8，Windows PowerShell 生成的 JSON 可以直接使用。

示例：

```json
{
  "enabled": true,
  "cache_backend": "redis",
  "lock_ttl_seconds": 600,
  "circuit_failure_threshold": 3,
  "circuit_cooldown_seconds": 900,
  "force_provider": false,
  "loop_idle_seconds": 5,
  "jobs": [
    {
      "name": "ashare-p1-sector-flow-news",
      "group": "ashare-p1",
      "enabled": true,
      "interval_seconds": 1800,
      "limit": 10,
      "market": "ashare",
      "params": {
        "industry": "银行",
        "concept": "融资融券",
        "flow_window": "5日",
        "ashare_symbol": "000001",
        "ashare_name": "平安银行"
      }
    },
    {
      "name": "crypto-spot-core",
      "group": "crypto",
      "enabled": true,
      "interval_seconds": 300,
      "limit": 20,
      "market": "crypto_spot",
      "params": {
        "crypto_symbol": "BTCUSDT",
        "crypto_timeframe": "1h",
        "crypto_market_type": "spot"
      }
    }
  ]
}
```

字段说明：

- `enabled`：全局开关，设为 `false` 时所有任务都不会执行。
- `cache_backend`：复用采集入口的缓存后端，可选 `auto`、`redis`、`null`。生产调度建议使用
  `redis`，确保任务锁和 Provider 熔断状态有效。
- `lock_ttl_seconds`：采集任务锁 TTL。
- `circuit_failure_threshold`：Provider 连续失败多少次后进入熔断。
- `circuit_cooldown_seconds`：Provider 熔断冷却时间。
- `force_provider`：是否忽略 Provider 熔断状态强制采集。
- `loop_idle_seconds`：loop 模式每次空闲检查的最大休眠秒数。
- `jobs[].enabled`：单任务开关。
- `jobs[].group`：采集分组，可选 `all`、`ashare-p0`、`ashare-p1`、`ashare-p2`、
  `ashare-risk`、`crypto`。
- `jobs[].interval_seconds`：loop 模式下该任务的采集间隔。
- `jobs[].limit`：传给基础采集入口的列表型任务条数。
- `jobs[].market`：调度层标记，便于区分 A 股和数字货币任务；当前不参与采集逻辑。
- `jobs[].params`：透传给 `collect_base_data.py` 的分组参数，例如 `ashare_symbol`、
  `risk_end`、`crypto_market_type` 等。

和主 Agent 的边界：

- 调度器只负责采集和归档基础数据。
- 调度器可以作为 `AlertService` 的前置触发来源，但不直接写 `decision_logs`。
- 持仓建议、观察池升级、换股比较和中文解释必须由 `PersonalFinanceAgent` 调用底层 Workflow 后生成。
- Redis 中的任务锁和 Provider 熔断只影响采集，不替代 PostgreSQL + TimescaleDB 中的事实记录。

使用外部配置运行：

```powershell
python scripts/data/run_base_data_scheduler.py --config base_data_scheduler.json --run-once
```
