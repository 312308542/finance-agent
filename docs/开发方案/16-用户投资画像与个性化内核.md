# 方案 16：用户投资画像与个性化内核

> 优先级：P0 ｜ 批次 6 ｜ 依赖：无（schema 必须最先定，17/18/19 都读它）
> 前置阅读：`14-选股能力与顾问层升级总纲.md`（尤其 §4 Hermes 边界、§5 红线原则）

## 1. 背景与现状

项目计划 §9.1 写的上层"私人金融助理"（懂你、引导、主动建议、会学）从未落地。代码现状（均以"零命中"坐实）：

- `orm.py` 无 `user_profile`/`risk_preference`/`investment_style` 任何实体。
- `chat.py` 无任何引导/追问/画像能力。
- 评分只有静态 `strategy:ashare:balanced_growth`，不读任何用户偏好。

结果：用户问"适合买入"，系统不知道"适合谁"，稳健者和赌徒拿到同一份清单。

**本方案是批次 6 的脊柱**——先把可审计的投资画像实体和工具接口固化，方案 17/18/19 才能统一读它。

## 2. 目标与非目标

**目标**

1. 新增**可审计、会演化的** `UserInvestmentProfile` 实体（风险偏好/周期/可投金额/风格倾向/择时习惯 + 各维置信度）。
2. 暴露 `profile.get` / `profile.upsert` / `advice.suggest_style` 工具（CLI + MCP），供 Hermes 和内部 Agent Loop 共用。
3. 实现**画像推断**：从持仓、确认/拒绝历史、复盘记录推断画像，给出"建议风格/择时姿态"的**可审计判断**。
4. 在方案 01 的 Hermes skill 文档里补**引导协议**（对话侧：何时问、问什么、怎么传达主动建议）。

**非目标**

- 不在 finance-agent 里建对话/引导循环（那是 Hermes 的活，本方案只暴露工具 + 推断判断）。
- 不让画像直接改 `total_score`（画像驱动的是权重选择和阈值，不是篡改确定性分数——红线）。
- 不做画像的真实模型联调（推断的模型增强归方案 10 统一联调）。

## 3. 技术方案

### 3.1 画像实体（迁移 `20260617_00XX_create_user_investment_profile.py`）

表 `user_investment_profiles`（PostgreSQL 普通表）：

| 列 | 说明 |
| --- | --- |
| profile_id (PK) | `profile:{owner_id}` |
| owner_id | 归属 |
| risk_appetite | conservative / balanced / aggressive |
| horizon | swing / mid_long / mixed |
| capital_scale | 可投金额量级（区间枚举，不存精确金额） |
| style_tendency (JSONB) | `{"value": 0.6, "theme": 0.4}` 价值↔题材倾向权重 |
| timing_posture | defensive / neutral / opportunistic（择时姿态） |
| dimension_confidence (JSONB) | 各维度画像的置信度（复用 O7 记忆置信度+半衰期机制） |
| source (JSONB) | 每维来源：elicited（问出来）/ inferred（推断）/ default（冷启动缺省） |
| status | active / stale |
| created_at / updated_at | |

设计要点：

- **冷启动**：新用户无画像时，返回 `default` 缺省画像（balanced / swing / value 偏重）+ `dimension_confidence` 全低，并标 `source=default`——不阻塞，让用户先能用，边用边学。
- **演化**：每次 elicited/inferred 更新对应维度并提升该维置信度；长期不更新的维度按半衰期衰减（复用 `decay_memory_confidence` 思路），衰减到阈值以下标 `stale`，提示 Hermes 重新确认。
- **画像也是一条 Finance Memory**：同步写 `assistant_memories(memory_type=investment_profile)`，保证审计可追溯（项目 §9.2 把"风险偏好"划归 Finance Memory）。

### 3.2 暴露工具（CLI + MCP，供 Hermes 驱动）

按既有 `FinanceToolRuntime` 只读/写工具模式新增：

| 工具 | 读写 | 说明 |
| --- | --- | --- |
| `profile.get` | 只读 | 返回画像 + 各维置信度 + 是否 stale；缺失返回缺省画像并标记 |
| `profile.upsert` | 写 | Hermes 把问出来/推断的画像维度落库，必带 `source` 和证据说明 |
| `advice.suggest_style` | 只读 | 返回"建议风格/择时姿态"的**可审计判断**（见 3.3），供 Hermes 传达 |

- `profile.upsert` 是**写工具**，必须进方案 01 工具边界测试的"写工具白名单"并显式评审（防回归）。
- 工具调用全程审计：谁、何时、改了哪维、依据什么。

### 3.3 画像推断与主动建议（finance-agent 的"判断"，可审计）

`advice.suggest_style` 的逻辑（确定性 + 可选模型增强）：

- **输入**：持仓结构、最近确认/拒绝决策历史（`decision_logs`）、复盘 outcome（`review_tasks`）、当前画像。
- **推断规则（确定性骨架）**：
  - 连续拒绝 N 次进取型建议 → 推断风险偏好偏保守，建议 `value` 偏重。
  - 持仓集中在低波动蓝筹 → 价值倾向；频繁追热点 → 题材倾向。
  - 复盘显示追高频繁亏损 → 建议 `timing_posture=defensive`。
- **输出**：`{建议 style_tendency, 建议 timing_posture, 依据列表（引用具体决策/复盘 ID）, 置信度}`——**这是判断不是事实**，但每条都可追溯。
- **模型增强（可选）**：复用方案 03/04 的 JSON 校验骨架让模型综合推断，失败回落确定性规则。**红线**：模型只能产出"建议"，不能改画像数值，落库仍走 `profile.upsert` 的确定性校验。

> **参考实现（Vibe-Trading，见项目计划 §13.3）**：其 **Trade Journal Analyzer**（解析券商导出 → 持仓天数/胜率/盈亏比 + 处置效应/过度交易/追涨/锚定诊断）和 **Shadow Account**（从交易记录提取规则）是"从用户真实行为推断画像"的成熟范式，T3 的确定性推断规则可直接借鉴其行为指标设计。其跨会话偏好记忆（"记住:我偏好 RSI、最大回撤 10%"）是 §3.4 引导协议的范式。**边界**：借鉴行为画像思路，但本项目画像落成可审计实体并驱动确定性评分，不让模型生成可执行策略。

### 3.4 Hermes skill 引导协议（写进方案 01 的 skill 文档，对话侧）

在 `docs/集成/Hermes金融助手Skill规范.md` 增补一节"投资画像引导"：

- **何时引导**：用户问选股/推荐类问题前，先 `profile.get`；缺失或 stale 维度 → 引导提问。
- **怎么问**：推断优先、提问最少。先看 `advice.suggest_style` 的推断，能推断的不问；必须问的一次最多 1~2 个，且要"值得问"（不变成问卷）。
- **怎么传达主动建议**：把 `advice.suggest_style` 的判断用人话说，并请用户确认（"看你的操作偏稳健，当前弱市，我建议偏价值、轻仓试，你看行吗？"）。
- **怎么记反馈**：用户确认/调整 → `profile.upsert` 落库（闭环：习惯学习）。
- 同步更新仓库副本与 Hermes 侧 skill（方案 01 已建立双向同步约定）。

## 6. 风险与注意事项

- **画像驱动什么、不驱动什么要划清**：画像选择评分**策略/权重**和买入**阈值**（方案 17 消费），但**绝不直接改** `total_score`/信号方向/风险标记。这条进防回归测试。
- 画像是概率性的，冷启动置信度低时，主动建议措辞要弱（"初步看…"），避免对不了解的用户下强结论。
- `advice.suggest_style` 的模型增强属真实模型调用，测试用 fake client，真实联调归方案 10。
- 写工具 `profile.upsert` 要防止 Hermes 误写覆盖——每次写带 `source` 和证据，且保留历史（不硬覆盖，可追溯演化）。
