# 方案 22：结构方法论引擎判别力修复与接入（structural-lite v2）

> 优先级：P0（阻塞方案 21 成果接入业务链路）｜ 批次 7 补强专项 ｜ 依赖：方案 21（引擎骨架）、方案 12（调度资源池）；阶段三依赖方案 15（真实数据）
> 前置阅读：`21-计算型方法论引擎完善方案.md`、`20-金融分析方法论技能库.md`
> 来源：总负责人独立技术复核（2026-07-03，含随机游走误报探针、前视偏差探针、增量重算探针、Vibe-Trading 参考实现对照）

## 1. 背景：复核结论与本方案定位

方案 21 交付的 `finance-agent-structural-lite`（`src/finance_agent/indicators/structural_methodology_adapters.py`）在**工程骨架**上合格：统一 payload、evidence_id、红线声明、skill 只读约束、增量重算稳定（250→260 根重算，20 组仅 1 个事件漂移）。这部分保留，不推翻。

但独立复核实测证明其**算法判别力不合格**，当前状态不能接入推荐证据链或圆桌上下文：

| 探针（30 条 250 日随机游走，纯噪声） | 实测结果 | 判定 |
| --- | --- | --- |
| 谐波检出率 | 30/30 = 100%，平均每条约 4 个"完成形态" | 零判别力 |
| Elliott `available` 率 | 30/30 = 100%，置信度均值 0.76（阈值 0.6） | 闸门失效 |
| SMC 结构事件 / FVG | 每条约 15 个事件、69 个 FVG，置信度顶格 0.85 | 噪声淹没 |
| 谐波形态新鲜度 | D 点距最新 bar 中位数 116 天，全部标 `complete` | 陈年形态主导输出 |
| 前视偏差 | BOS 时间戳可早于 swing 实际可确认时间最多 `window` 根 bar | 回测/评分不可用 |

**根因（对照 `D:\Code\aiAgents\Vibe-Trading` 参考实现后确认）**：

1. 谐波分类器**移植缺失**——Vibe-Trading `harmonic/example_signal_engine.py` 的 `PATTERNS` 表每形态定义 4 个比例（`b_retrace`/`d_retrace`/`bc_ratio`/`cd_ratio`），本项目 `classify_harmonic` 的 `rules` 只保留前两个，`bc_ratio`/`cd_ratio` 算了但从不校验。
2. 默认参数过于激进——本项目 `swing_window=3`，参考实现为 10 且注释明确"值越大越可靠"；实测窗口 3→10 可使噪声减少约 2/3。
3. 置信度体系未在噪声基准上校准——SMC 置信度公式方向性错误（事件越多分越高），Elliott 候选整批泄漏。
4. 测试只有 4 个合成正样本，全部用 `swing_window=1`，生产默认参数路径零覆盖，无任何假阳性/边界测试。

本方案目标：**把 structural-lite 从"能跑出合成样例"升级为"能区分结构与噪声"，并完成从引擎到调度、入库、圆桌、前端的完整业务接入。** 分三阶段：判别力修复（v2 引擎）→ 系统接入 → 真实数据校准与价值验证。

## 2. 目标与非目标

**目标**

1. 四类误报在固定噪声基准上降到可接受水平（验收线见 §7），并用回归测试锁死。
2. 消除前视偏差：所有结构事件带 `confirmed_at_bar`/`confirmed_at` 的 as-of 语义。
3. 结构证据接入业务链路：收盘后批量计算候选池 → 写 `indicator_frames` → 圆桌技术分析师可引用 → 前端个股页可见。
4. 真实数据上完成参数校准与黄金样本回归，并给出"结构信号是否有信息量"的事件研究结论。

**非目标**

- 不推翻方案 21 的 payload 骨架、红线协议和 skill 约束（已合格）。
- 结构信号**不进入评分权重**（`asset_scores`），只做解释证据、风险提示与等待/失效条件——除非阶段三事件研究证明有信息量并经总负责人批准。
- 阶段一、二不引入外部库；czsc/pyharmonics/smartmoneyconcepts 的评估归阶段三决策项 D1。
- 不做盘中实时结构计算（无消费方，且 A 股日线是第一版主场景）。

## 3. 阶段一：判别力修复（引擎 v2）

以下按缺陷逐项给出代码位置、修复规格与验收断言。全部修复后 `ENGINE_VERSION` 升为新日期版，`schema_version` 各升 `*_v2`。

### 3.1 F1 谐波：补全四比例校验（对应复核 P0-1）

**位置**：`structural_methodology_adapters.py` `classify_harmonic()`（现第 310-355 行）。

**修复规格**：

1. `rules` 表补全为四比例，数值直接采用 Vibe-Trading `PATTERNS`（已对照标准 Carney 定义验证）：

```python
RULES = {
    "Gartley":   {"b_retrace": (0.55, 0.68), "d_retrace": (0.72, 0.84),
                  "bc_ratio": (0.382, 0.886), "cd_ratio": (1.27, 1.618)},
    "Bat":       {"b_retrace": (0.33, 0.55), "d_retrace": (0.82, 0.94),
                  "bc_ratio": (0.382, 0.886), "cd_ratio": (1.618, 2.618)},
    "Butterfly": {"b_retrace": (0.72, 0.84), "d_retrace": (1.20, 1.38),
                  "bc_ratio": (0.382, 0.886), "cd_ratio": (1.618, 2.618)},
    "Crab":      {"b_retrace": (0.33, 0.68), "d_retrace": (1.52, 1.72),
                  "bc_ratio": (0.382, 0.886), "cd_ratio": (2.24, 3.618)},
}
```

2. 匹配时**四个比例全部校验**，任一不中即不匹配该形态。
3. 容差从绝对值 ±0.12 改为**相对容差**：`in_range(value, bounds, rel_tol=0.10)` 即区间边界各放宽 `bound*rel_tol`（低比例不再被过度放宽）。
4. 多形态命中时**按 fit 择优**而非 dict 顺序 first-match：对每个命中的形态计算四比例 fit 分，取最高者；`harmonic_fit_score` 从只看 b/d 两项扩为四项均值。
5. 新增**新鲜度字段与过滤**：`bars_since_d = len(bars) - 1 - d.bar_index`；payload 每个形态带 `bars_since_d`；新增适配器参数 `harmonic_max_bars_since_d: int = 10`，超过则不输出（可配，审计场景可调大）。`completion` 字段仅当 `bars_since_d == 0` 为 `"forming_or_just_completed"`，否则 `"complete"`。

**验收断言**：合成 Bat 比例序列不再被判为 Gartley；D 点在 60 根 bar 前的形态默认不输出；噪声基准检出率达标（§7）。

### 3.2 F2 默认参数对齐参考实现（对应复核参数对照）

**位置**：`StructuralMethodologyAdapter.__init__`。

**修复规格**：

1. `swing_window` 默认 3 → **10**（对照 Vibe-Trading；实测噪声降 2/3）。
2. 新增最小数据量保护：各 `compute_*` 在 `len(bars) < swing_window * 4` 时直接返回 `status="insufficient_data"`（沿用统一 payload，`candidates/patterns/events` 为空），不强行出结构。
3. 现有测试样例继续用小窗口显式传参（`swing_window=1`），**另** 为默认参数路径新增测试（见 §5）。

### 3.3 F3 SMC：置信度重定义 + FVG 降噪（对应复核 P0-3 / P1-5）

**位置**：`compute_smc()`（第 147-150 行置信度公式）、`detect_fair_value_gaps()`。

**修复规格**：

1. **删除**"事件越多置信度越高"公式。置信度改为**逐事件**计算并取消 payload 顶层聚合置信度（或顶层改为 `max(event confidences)` 并注明口径）：
   - BOS/CHoCH 事件置信度 = f(突破幅度/参考 swing 价格, 突破 bar 的实体占比)：`min(0.9, 0.5 + 4 * break_pct + 0.2 * body_ratio)`，其中 `break_pct = (close - break_level)/break_level` 的绝对值。系数在阶段三真实数据上复核。
2. FVG 增加 **ATR 相对宽度地板**：先算 14 期简单 ATR（引擎内自足实现，不依赖 ta-lib），`width < 0.3 * ATR` 的缺口丢弃（阈值可配 `fvg_min_atr_ratio: float = 0.3`）。
3. FVG 增加**回补状态**：向后扫描，若后续任意 bar 区间触及缺口区间则标 `mitigated: true` 与 `mitigated_at`；默认输出参数 `fvg_include_mitigated: bool = False`（已回补缺口不再输出）。
4. FVG 置信度与宽度挂钩：`min(0.85, 0.5 + width/ATR * 0.2)`，替换硬编码 0.6。

**验收断言**：噪声基准上每 250 根 bar 的 FVG 输出 ≤ 8 个；SMC payload 不再出现"事件数堆出 0.85"。

### 3.4 F4 as-of 语义：消除前视偏差（对应复核 P1-4）

**位置**：`detect_swings()`、`detect_structure_breaks()`、各事件/形态序列化。

**修复规格**：

1. `SwingPoint` 增加 `confirmed_bar_index = bar_index + window`（swing 在其后第 `window` 根 bar 收盘才可确认）。
2. `detect_structure_breaks()` 的可用性判断从 `point.bar_index < index` 改为 **`point.confirmed_bar_index <= index`**——只有已确认的 swing 才能被"突破"。
3. 所有输出对象（结构事件、谐波形态、Elliott 候选）统一带 `confirmed_at_bar` / `confirmed_at`（ISO 时间）：事件确认时间 = max(触发 bar, 所引用全部 swing 的确认 bar)；谐波/Elliott 的确认时间 = D 点/末浪 swing 确认 bar 对应时间。
4. payload 顶层新增 `as_of_semantics: "confirmed_only"` 声明，供回测与审计识别。

**验收断言**：专项测试构造"swing 尚未确认即被价格穿越"的序列，断言不产生事件；全部事件 `confirmed_at >= 引用 swing 的确认时间`。

### 3.5 F5 Elliott：逐候选过滤 + 置信度重校准 + 失效语义修正（对应复核 P0-2 / P2-6②）

**位置**：`compute_elliott()`（第 191-197 行）、`classify_abc()`、`elliott_candidate()`。

**修复规格**：

1. **逐候选过滤**：`candidates = [c for c in candidates if c["confidence"] >= threshold]`，替换"最高分过线整批放行"。
2. 移植 Vibe-Trading Elliott 引擎的两层过滤（`elliott-wave/example_signal_engine.py`）：
   - `_check_fib_ratios` 思路：浪比校验从加分项改为**硬门槛**（r2∈[0.236,0.786]、r3/r1≥1.0、r4 回撤∈[0.236,0.5] 大幅收窄现有 [0.2,0.65]）；不满足直接拒绝而非低分通过。
   - `_check_min_bars` 思路：每浪至少跨 `min_bars_per_wave: int = 3` 根 bar，过滤 swing 毛刺拼出的"假浪"。
3. ABC 的硬编码 0.66 改为按 wave_b/wave_a、wave_c/wave_a 靠近经典比例（0.5/0.618、1.0/1.618）的程度打分，范围 [0.5, 0.8]。
4. 基础分下调：`impulse_confidence` 起步分 0.55 → 0.4，使"仅满足铁律、比例不佳"的候选自然低于 0.6 阈值。
5. **失效语义修正**：`invalidation_price` 当前取 4 浪端点，但对"完成→衰竭"假设，突破末浪端点方向才是失效。改为输出两个字段：`thesis_confirmation_price`（跌破 4 浪低点=衰竭确认，bullish 场景）与 `thesis_invalidation_price`（突破 5 浪高点=衰竭假设失效）。skill 文档同步更新解读口径。

**验收断言**：噪声基准 Elliott `available` 率 ≤ 30%；返回的每个候选置信度均 ≥ 阈值；语义字段两个价位方向正确。

### 3.6 F6 次要修复（一并处理）

1. **等高极值**：`detect_swings` 唯一性判定改为"取窗口内首个等值极值"而非直接丢弃（A 股一字板平台、等高双顶不再系统性漏检）。实现：`count_value(...) == 1` 放宽为 `section.index(current) 是首个等值位置`。
2. **schema 一致性**：`compute_swings` 补顶层 `confidence`（可按 swing 数量/bar 数的结构清晰度给出保守值），四引擎 payload 字段集合对齐。
3. **形态去重**：谐波输出对重叠时间窗的同名形态去重（保留 fit 最高者）。
4. `normalize_bars` 增加同 timestamp 去重（保留后者）与告警计数。

## 4. 阶段二：系统接入

### 4.1 接入模式决策（复核 Q6 结论落地）

**收盘后定时批量、只算候选池、写 `indicator_frames`。** 不做实时（无盘中消费方）；不做圆桌前按需算（同一 run 不可复现，违背审计原则）。

### 4.2 调度任务

按方案 02/12 的既有接入模式：

- `sync_config.py` 新增 `sync_task_type = analytics.structural_methodology`，任务 `analytics.structural.ashare.daily`：
  - 触发：挂 `ashare.bars.1d.close_final` 的 `after_success`。
  - 资源池：`analytics`（方案 12），优先级 540（低于技术初筛 550，因为它消费初筛结果）。
  - 参数：`engines: ["swings","smc","harmonic","elliott","ichimoku"]`（可裁剪；Ichimoku 由方案 23 阶段二追加）、`scope`（默认 技术初筛池 ∪ 持仓 ∪ 用户观察池 ∪ 研究池，几百只规模）、`timeframe: 1d`、`lookback_bars: 250` 及 §3 各引擎阈值参数（前端任务配置页可调）。
- `BaseDataScheduler` 新增执行入口 `run_structural_methodology_refresh(**kwargs)`（仿 `run_technical_screening_refresh`），payload 写入各引擎的 `computed/insufficient/error` 计数。

### 4.3 入库

- 复用 `indicator_frames`（不建新表）：`library = "structural-lite"`，`indicator_key = schema_version`（如 `smc_lite_v2`），payload 即引擎输出。evidence_id 已具备确定性（同输入同 id），天然幂等 upsert。
- 写入前置过滤：`status in {"insufficient_data","insufficient_structure","no_pattern","no_structure_event"}` 的结果**也写入**（记录"无结构"本身是证据），但 payload 精简为状态与元数据。

### 4.4 圆桌与工具层

- `FinanceToolRuntime` 的 `factor.get_asset_factor_context`（或新增 `structure.get_asset_context` 只读工具）透出最近一次 structural-lite 各引擎结果。
- 圆桌 `technical_analyst` 节点上下文注入结构证据；skill（harmonic/elliott-wave/smc，方案 21 已改只读版）无需再改——它们本来就只解读引擎输出。
- **分级使用（复核 Q3/Q7 结论落地）**：
  - Swing 趋势段：可进技术分析师常规上下文（最可信）。
  - SMC BOS/CHoCH（v2 置信度）：解释证据；持仓标的出现反向 CHoCH 时，允许作为**风险提示**进入风险反驳角色上下文。
  - 谐波、Elliott：仅"潜在反转结构"叙事与**等待/失效条件**（如"若回踩不破 X 则……"）。
  - FVG：仅未回补且宽度达标的，作为"价格磁吸/风险区间"叙事。
  - **全部不进评分**。防回归测试断言 `ScoringService`/推荐动作路径无 structural 引用。

### 4.5 前端

- 方案 07 的报告/个股详情页增量：结构证据卡片（引擎、schema、置信度、confirmed_at、caveats 原样展示）。设计原则：**证据完整度如实呈现**，低置信度/insufficient 状态也显示，不粉饰。

## 6. 阶段三：真实数据校准与价值验证（依赖方案 15）

1. **参数校准**：候选池真实日 K 上跑 v2 全引擎，统计各引擎触发率/置信度分布；调整 `swing_window`、容差、FVG 地板、Elliott 门槛至"日常约 5-15% 标的有结构证据"的可用密度（拍板值记录进本方案附录）。
2. **黄金样本**：选 2-3 只代表性 A 股（建议 600519 + 一只高波动题材股 + 一只一字板经历股）固定区间，人工审阅引擎输出并固化 golden 测试。
3. **事件研究（复核 Q7 的最终裁决）**：用方案 09 回测骨架对各结构信号做前向收益研究（信号后 5/10/20 日超额收益 vs 候选池基准）。结论三分：有信息量→保留并可提案进风险提示权重（须总负责人批准）；无信息量→降级纯叙事；负信息量→下线该信号。
4. **D1 决策项（外部库）**：阶段三结束时评估——czsc（缠论，A 股认知度高，方案 20 已留接口，**优先级最高**）；pyharmonics / smartmoneyconcepts 仅在自研 v2 修复后仍不满意时，经既有扩展点 A/B 对比再决定。默认不引入。

## 9. 风险与注意事项

- **T3（as-of）会减少事件数量**——确认延迟意味着突破发生时若 swing 未确认则不再报事件。这是**正确的行为**，测试期望值要按新语义写，不要为了保住旧测试数字而放水。

- `swing_window=10` 后短周期结构（<1 个月）不可见。这是日线选股场景的正确取舍；若未来做 30/60 分钟结构，另配窗口参数，不回调日线默认值。
- Elliott 即使修复后仍是四引擎中最主观的：置信度天花板压在 0.9，报告措辞永远用"候选浪型"，绝不用"第 X 浪"的确定性表述。

- 本方案完成前，方案 21 的输出**不得**被任何业务链路消费（当前恰好未接入，保持现状即可）。
