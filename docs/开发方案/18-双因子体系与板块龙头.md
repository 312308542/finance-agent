# 方案 18：双因子体系与板块龙头

> 优先级：P1 ｜ 批次 6 ｜ 依赖：方案 15（板块/资金流真实数据）、方案 16（画像，决定走哪套）；与方案 17 评分校准**同步**
> 前置阅读：`14-选股能力与顾问层升级总纲.md`

## 1. 背景与现状

现有因子体系是**价值投资底子**（技术/基本面/估值/资金流/事件/风险），稳，但 A 股短期赚钱效应主要来自**题材/游资/龙头**，现有因子完全没覆盖这一维度。

用户的产品决策（已确认）：**两套并行，按用户偏好切换，且 Agent 要能主动建议用哪套**——像私人金融助手。

**红线提醒（总纲 §5）**："找龙头"绝不能让 LLM 凭训练知识说哪个板块热（幻觉 + 违反"事实只来自入库"）。龙头和热门板块**必须从已入库数据确定性算出来**——系统已采板块/概念成分、资金流榜、人气榜、涨停池，数据齐（方案 15 保证覆盖），缺的是把它们算成"板块强度 + 龙头"的确定性层。

> **参考实现（Vibe-Trading，见项目计划 §13.3）**：其 `sector-rotation`（板块轮动）skill、`multi-factor` 与 Alpha Zoo（456 因子库）、swarm 圆桌预设（`investment_committee` 多空辩论、`technical_analysis_panel`、`risk_committee`）分别可参考本方案的板块强度/题材因子（§3.1-3.3）和圆桌补角色（§3.4）。**边界**：因子/板块由确定性服务算，借鉴其因子设计与圆桌编排，但不让 LLM 挑板块或生成策略代码。

## 2. 目标与非目标

**目标**

1. 新增**板块强度 + 龙头识别**确定性服务（从已入库数据算，可审计、带证据）。
2. 形成**两套因子/评分体系**：`value`（现有，微调）和 `theme`（新，题材/龙头导向），由画像选择或融合。
3. 补回总纲 §1.2 缺失的**事件分析师 + 资金流分析师**圆桌角色，让新维度有人解读。
4. 题材体系产出的龙头候选，天然带"可买入性"标记（一字板预警，方案 19 校验）。

**非目标**

- 不引入机器学习/ML 打分（仍后置）。
- 不让模型挑板块（确定性服务挑，模型只解读）。
- 不删现有价值因子（它是稳健用户的体系，也是测试基线）。

## 3. 技术方案

### 3.1 板块强度服务（确定性）

新增 `application/sector_strength_service.py`：

- 按板块（行业/概念）聚合成分股的：资金净流入、区间涨幅、涨停数、人气热度、上榜频次。
- 产出**热门板块排名**（确定性，每项带证据 ID 指向源数据）。
- 输出 `SectorStrength{sector_id, 强度分, 资金流, 涨停数, 连续性, evidence_ids}`。

### 3.2 龙头识别服务（确定性）

`application/leader_detection_service.py`：

- 在强板块内，按**相对强度 + 资金流排名 + 涨停时间（首板/连板高度）**排序，识别龙头/跟风/补涨。
- 这是 A 股游资/题材逻辑的可量化版本，全部基于入库数据。
- 输出 `LeaderRank{asset_id, sector_id, 龙头位次, 连板高度, 相对强度, 可买入性预警, evidence_ids}`。
- **可买入性预警**：一字涨停/停牌的龙头标 `unbuyable`，供方案 19 和报告显著提示。

### 3.3 双因子体系

- 新增因子组 `sector_strength` / `leadership`（题材体系专用），通过候选成员 payload 或生产题材上下文服务注入 `factor_frames`；真实截面是否稳定出现取决于行业/概念成员池覆盖。
- 新增评分策略 `strategy:ashare:theme_momentum`（题材动量），权重偏向板块强度、龙头位次、资金流、人气；与现有 `balanced_growth`（价值）并列。复用方案 05 的 `scoring_strategies` 表机制。
- **画像驱动选择**：`ScoringService` 按画像 `style_tendency` 选策略——纯价值→value 策略、纯题材→theme 策略、混合→两套都算并按权重融合排序（产出两个分，融合分 = value×w_v + theme×w_t）。
- **关键：与方案 17 同步**——新因子改变评分构成，方案 17 的相对分位校准必须基于"加了新因子后"的真实分布，否则校准两次。

### 3.4 圆桌补角色

在 `roundtable_prompts.py` 补回两个角色（治总纲 §1.2）：

- `event_analyst`（市场事件分析师）：解读新闻、公告、舆情、监管、题材——评分层已算的 `event`/`event_decay` 因子终于有人讲。
- `flow_analyst`（资金流/衍生品分析师）：解读个股资金流、北向、板块资金、龙虎榜席位。
- 每个角色 prompt 加**数据维度自检**（治总纲 §1.2 被动质疑问题）：必须声明"本次覆盖/缺失哪些维度"，`data_gaps` 必填。
- 风险反驳员加一条："数据维度缺失本身是一条反方观点"。

## 6. 风险与注意事项

- **红线核心**：板块/龙头是确定性服务算的，模型只解读不挑选。任何"让模型说哪个板块热"的实现都要被拦截，加防回归测试。
- 题材因子波动大、噪声高，`theme_momentum` 策略要配更强的风险反驳和可买入性校验，避免推一堆追不进的连板。
- 与方案 17 的同步是硬约束：T6 联合校准不能省，否则评分分布被新因子打乱。
- 价值因子和现有评分测试是基线，不许删。
