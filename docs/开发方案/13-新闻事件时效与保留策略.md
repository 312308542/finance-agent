# 13-新闻事件时效与保留策略

## 1. 背景

A 股新闻、公告和事件源会随时间持续增长。`event_records` 和 `evidence` 保存的是已经清洗过的事实，`raw_records` 保存的是 Provider 原始响应审计。它们都不能简单等同于“当前仍有效的交易信号”。

当前链路已经完成盘中重点资产新闻和盘后全量新闻拆分：

- `ashare.events`：盘中高频，只覆盖重点池、观察池、研究池、技术初筛池和最近推荐中的可交易主板标的。
- `ashare.events.full`：盘后低频，覆盖可交易 A 股主板资产池。
- `ashare.news_articles`：异步补抓正文，并回填 `event_records.payload.article` 和 `evidence.payload.article`。
- `ashare.news_retention`：后台维护任务，定时删除过期新闻/公告事件和证据行。

但在保留策略上还存在两个缺口：

1. Agent 和因子读取最近事件时只按 latest N 限制，没有默认时间窗口，长时间无新事件的标的可能把很旧新闻当成“最近事件”。
2. 新闻/公告作为强时效事件源会持续增长，过期后继续保留在 `event_records` 和 `evidence` 会污染当前观察链路并造成表体积膨胀。

## 2. 目标

- 默认只把最近 90 天新闻/公告作为 Agent 和因子层的“当前有效事件输入”。
- 过期新闻/公告不再保留在事件事实层，定时删除 `event_records` 和 `evidence` 中对应整行。
- `raw_records` 作为 Provider 原始响应审计暂不自动删除，避免排错链路断掉。
- 文档化三层时效：原始审计、事件事实、交易信号。

## 3. 非目标

- 不修改新闻采集频率和资产范围。
- 不删除 `raw_records`。
- 不新增归档表或冷存储流程。
- 不引入 LLM 新闻清洗或摘要生成。
- 不改变因子事件衰减公式，只控制进入衰减计算的默认事件窗口。

## 4. 设计

### 4.1 事件有效窗口

新增统一常量：

- `DEFAULT_EVENT_SIGNAL_LOOKBACK_DAYS = 90`
- `DEFAULT_ARTICLE_FULL_TEXT_RETENTION_DAYS = 90`
- `NEWS_ARTICLE_EVENT_TYPES = ("news", "announcement")`

`EventRepository.list_recent_events()` 增加 `max_age_days` 参数，默认 90 天。筛选规则使用事件时间：

```text
event_time = published_at if published_at is not null else collected_at
event_time >= now - max_age_days
```

`FactorService.compute_for_asset()` 继续调用 `list_recent_events()`，因此默认只消费 90 天内事件。

`AgentContextBuilder._load_recent_events()` 使用同一默认窗口，避免上下文把长期旧新闻传给模型。

### 4.2 过期事件保留策略

新增仓储方法：

```text
EventRepository.delete_expired_article_events(...)
```

该方法同时处理：

- `event_records`
- `evidence`

满足以下条件才删除：

- 事件类型属于 `news` 或 `announcement`。
- 事件时间早于保留 cutoff。

清理会删除过期事件和证据整行，不删除 `raw_records`。

### 4.3 后台定时清理任务

新增调度任务 `ashare.news_retention`，作为后台维护任务每天 19:10 执行一次。任务参数为：

- `sync_task_type=event_article_retention`
- `article_retention_days=90`
- `resource_pool=maintenance`
- `mutex_key=ashare.event_records`

该任务与新闻采集、正文补抓共享事件表互斥键，避免在正文补抓回填时同时删除同一事件。任务只调用 `EventRepository.delete_expired_article_events()`，不会触发新闻采集，也不会删除 `raw_records`。

### 4.4 分层保留原则

| 层级 | 表 | 保留策略 | 用途 |
| --- | --- | --- | --- |
| 原始审计 | `raw_records` | 暂不自动删除 | 排错、追溯、供应商响应审计 |
| 事件事实 | `event_records` / `evidence` | 新闻/公告默认 90 天后删除 | 当前事件事实、证据索引 |
| 当前信号 | Agent 上下文 / 因子输入 | 默认 90 天窗口 + 事件衰减 | 推荐、风险、盘中分析 |
