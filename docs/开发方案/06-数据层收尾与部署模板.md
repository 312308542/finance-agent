# 方案 06：数据层收尾与部署模板（O5 尾巴）

> 优先级：P1 ｜ 批次 3 ｜ 依赖：无（可与批次 2/3 其他方案并行）
> 前置阅读：`00-总体规划与执行约定.md`

## 1. 背景与现状

数据层生产化主体已完成（任务队列通用化 DSQ-001~014、水位增量、按源限流、K 线生命周期、基金接入、任务监控）。剩余三类尾巴：

1. **基金阻塞项**（`docs/基金行情同步任务方案.md` 自报）：
   - FUND-013：小批量 LOF 10 年日 K 验证——东方财富主源超时，无 AKShare 现成备源。
   - FUND-015：全量基金初始化——受 FUND-013 拖累不能放量。
2. **A 股风险/资金数据缺口**（`docs/项目进度跟踪表.md` 自报）：北向资金多窗口、限售解禁、股权质押未接入。
3. **部署模板缺失**：调度器 `--loop` 常驻能力已有，但没有容器 / Windows 任务计划 / 服务化模板，目前靠手工命令行拉起。

## 2. 目标与非目标

**目标**

1. LOF 历史 K 线打通备源，解除 FUND-013/015 阻塞，完成全量基金初始化放量。
2. 北向资金、限售解禁、股权质押三类数据接入采集→落库→风险/因子消费链。
3. 提供可复制的常驻部署模板（Windows 任务计划为主，Docker 为辅）与运维 runbook。

**非目标**

- 不接链上/宏观事件（仍是后续增强）。
- 不做正式限流监控大盘（任务监控页已有源级状态展示，够用）。

## 3. 技术方案

### 3.1 LOF 历史 K 线备源（解除 FUND-013/015）

**关键洞察**：LOF 是交易所交易品种（sh5/sz16 开头），与 A 股共享交易所行情通道。仓库已有绕开 AKShare 的直连实现 `src/finance_agent/data/providers/ashare_kline_sources.py`（`fetch_tencent_kline_direct` / `fetch_eastmoney_kline_direct`，含 2 年窗口分页 `two_year_windows`）。

方案：

- 在 `akshare_fund_provider.py` 的 `fetch_lof_ohlcv` 失败链上增加腾讯直连备源：复用 `fetch_tencent_kline_direct`，symbol 映射用现有 `_sina_fund_symbol` 风格的交易所前缀推断（`infer_fund_exchange` 已在 normalizers 中实现）。
- 接入 `ProviderChain`（`scheduler/task_queue_model.py`）作为第二源，失败审计自动进 `ProviderAttempt`。
- ETF 同步受益：同一备源对 ETF 历史 K 线同样适用，作为现有主源的兜底。
- 验证路径：先跑 FUND-013 小批量（10 只 LOF × 10 年），抽样比对腾讯 vs 东财数据一致性（收盘价偏差 < 0.1% 容忍，复权口径写清楚——直连源是否前复权必须实测确认并记录在基金方案文档）。
- 放量（FUND-015）：沿用 `ashare.bars.1d.bootstrap` 的断点续跑模式，分批执行 `fund.etf.bars.1d.bootstrap` / `fund.lof.bars.1d.bootstrap` / `fund.open.nav.bootstrap`，水位表防重。

### 3.2 北向资金 / 限售解禁 / 股权质押接入

按既有 Collector 模式（参考 `AshareRiskSentimentCollector` 的接法：Provider → 能力注册 → Collector → raw_records 归档 → 业务表 → sync_task_type 分发）：

| 数据 | AKShare 接口（实现时以当版 AKShare 实测为准） | 落库 | 下游消费 |
| --- | --- | --- | --- |
| 北向资金（市场级历史） | `stock_hsgt_hist_em` | `capital_flow_snapshots`（市场级 asset_id 约定，沿用现有榜单级水位风格） | 资金流因子北向多窗口 |
| 北向持股（个股） | `stock_hsgt_individual_em`（或当版等价接口） | `capital_flow_snapshots` | 个股北向因子 |
| 限售解禁 | `stock_restricted_release_queue_em` | `event_records`（event_type=`restricted_release`）+ 临近解禁写 `risk_findings` | 事件因子、风险反驳 |
| 股权质押 | `stock_gpzy_pledge_ratio_em` 等 | `risk_findings`（质押比例超阈值） | 风险反驳、回避池 |

实现约束：

- 全部走 SourceGate 限流（eastmoney host 既有策略）+ 失败水位冷却，单接口失败不阻塞批次（DSQ 模式）。
- 每个接口先在 `docs/AKShare能力矩阵.md` 登记（接口名、字段、频率、失败模式），再写代码——这是仓库既有纪律。
- 新增 `sync_task_type`：`ashare.northbound`、`ashare.restricted_release`、`ashare.pledge`，纳入 `data config` 预设（低频：日级/周级）。
- 风险阈值参数化进任务 params（解禁市值占比、质押比例红线）。

### 3.3 部署模板与 runbook

新增 `deploy/` 目录：

1. **Windows 任务计划（主推，当前生产环境）**：
   - `deploy/windows/register_scheduler_task.ps1`：用 `Register-ScheduledTask` 注册开机自启 + 失败重启的调度器常驻任务（`run_base_data_scheduler.py --loop --status-file ... --event-log-file ...`）；参数化安装路径；附卸载脚本。
   - `deploy/windows/register_api_task.ps1`：同模式注册 API 服务常驻任务（`uvicorn finance_agent.api.app:app --app-dir src --host 127.0.0.1 --port 8000`）。前端生产形态用 `npm run build` 产物，由 API 进程托管静态文件或本机 IIS/nginx 指向 `apps/agent-office/dist`（模板二选一给出，默认 API 托管，改动最小）。
   - `deploy/windows/README.md`：安装、查看状态、日志位置、升级流程（停任务→git pull→alembic upgrade→重启）。
   - 安全注意：API 默认只绑 `127.0.0.1`；模板注释明确"如需局域网访问必须自行加反向代理与鉴权"——当前 API 无认证层，不得直接暴露。
2. **Docker（辅）**：
   - `deploy/docker/Dockerfile.scheduler` + compose 片段（挂载 runtime/、连接既有 postgres/redis 服务）；注意 TA-Lib 系统依赖的安装层。
3. **runbook**：`docs/运维手册.md`——常驻进程健康判定（状态文件心跳）、常见故障（Redis 断连降级、源熔断、Cookie 过期跑 `refresh_eastmoney_cookie.py`）、数据缺口补采流程（`check_base_data_health.py` → backfill_jobs）。

### 3.4 决策项 D1：`market_bars_intraday` 表的去留

迁移 0015 建了分钟级 K 线表，但当前**没有任何写入方**（只有 ORM 定义），盘中能力实际由 `ashare.realtime_quotes`（5 分钟实时快照）承担。本方案需要做一次显式决策并落档：

- **选项 A（推荐）**：暂不建分钟 K 线采集任务。理由：实时快照已满足方案 02 盘中触发的需要；分钟 K 线全市场采集的限流与存储成本高，而第一版投资周期是中长期+波段（项目计划 §3.2），分钟级数据无消费方。表保留，在 `docs/数据库设计.md` 标注"预留，无写入方"。
- **选项 B**：仅对持仓+用户观察池小范围采集分钟 K 线（复用 K 线生命周期任务模式，新增 `sync_task_type=market_bars_intraday_refresh`，限定资产清单来自 `EventPriorityResolver`）。在确有盘中精细分析需求时升级到此选项。

执行者按选项 A 落实，除非总负责人在进度表批注改走 B。

## 6. 风险与注意事项

- 直连源的复权口径是最大数据质量风险：实测确认腾讯接口复权方式与现有 `market_bars` 入库口径一致后才能放量；不一致就在归一化层转换并写明。
- AKShare 接口名随版本漂移，T3-T5 动手前先 `python -c "import akshare; help(...)"` 实测当版接口签名，登记进能力矩阵。
- 放量初始化要尊重既有源限流（`source_rate_limiter` 默认策略），不要为了快调大并发——东财封禁的恢复成本远高于慢一点。
- `deploy/` 模板里不得出现真实密码/key，数据库 URL 用占位符。
