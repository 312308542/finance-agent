## 2. 目标与非目标

**目标**

1. 配置真实 DeepSeek V4 Pro（常规分析）和 GPT-5.5 Pro（高风险复核），完成全链路端到端真实运行一次。
2. 每个待联调项产出脱敏的真实请求/响应样本，归档进对应方案文档附录。
3. 真实数据回测产出合理性经人工审阅的绩效结果。
4. 暴露并修复仅在真实环境才会出现的问题（编码、超时、限流、JSON 漂移、成本）。

**非目标**

- 不改任何已通过测试的业务逻辑——除非真实联调暴露出确定性缺陷（暴露了就按 TDD 补测试再修）。
- 不接真实交易（红线不变）。
- 不做性能压测和并发调优（归后续运维阶段）。

## 3.2 模型配置（不进代码、不进 .env 提交）

通过既有 `models` CLI 把真实 key 写入数据库：

```powershell
.\.venv\Scripts\python.exe -m finance_agent.cli models init `
  --deepseek-base-url https://api.deepseek.com/v1 `
  --deepseek-api-key "<真实 key>"
.\.venv\Scripts\python.exe -m finance_agent.cli models set-provider --provider openai --base-url <...> --api-key "<真实 key>"
.\.venv\Scripts\python.exe -m finance_agent.cli models set-route --role analysis --model deepseek-v4-pro
.\.venv\Scripts\python.exe -m finance_agent.cli models set-route --role high_risk_review --model gpt-5.5-pro
.\.venv\Scripts\python.exe -m finance_agent.cli models route-preview   # 确认路由
.\.venv\Scripts\python.exe -m finance_agent.cli models test --role analysis   # 单次连通性 dry-run
```

安全：key 只进数据库；联调结束后总负责人决定是否保留或轮换；任何样本入档前脱敏（base_url、key、token 用量保留量级即可）。

## 3.3 分项联调（每项独立可回退，失败不影响其他项）

### L1 圆桌真实模型（04-T6）
- 跑 `finance-agent workflows run asset_deep_analysis`（用真实有数据的 owner/asset）。
- 人工审阅五角色观点：① `generated_by=model` 是否生效；② 每条 key_point 能否追溯到工具上下文；③ **风险反驳是否言之有物**（重点，不能是套话）；④ evidence_ids 是否都在上下文白名单内（凭空引用应已被剔除进 data_gaps）。
- 拔掉模型配置重跑一次，确认 fallback 到规则版且报告标注来源。
- 样本存 `04` 方案附录（脱敏）。

### L2 高风险复核回写（03-T6）
- 构造一条卖出/换股裁决（真实数据触发或手工造待复核事件）。
- 跑 `finance-agent agent review-pending --owner-id ... --limit 5`（去掉 dry-run）。
- 验证审计链可追溯：`model_route → model_review → model_review_result`；reject 的决策在 `decision_logs` 状态为 `rejected_by_review`。
- 断网/错 key 重跑一次，确认 `review_unavailable` 且不默认放行、置信度打折。
- 样本存 `03` 方案附录。

### L3 端到端主链路 + 前端确认（07-T8）
- 真实跑一轮：触发 → Workflow → 报告落库 → 前端报告页可见 → 推荐页点「确认接受」→ 生成订单草案 → 「执行登记」→ 持仓更新 → 复盘任务生成。

## 6. 风险与注意事项

- **成本控制**：圆桌 6 Workflow × 5 角色全开 + 复核，真实调用费用可观。联调先用 `roundtable_model_roles` 收缩到 `["risk_rebuttal","portfolio_manager"]`，单 Workflow 验证通过再全开；记录每次联调的 token 量级。
- **模型质量问题 ≠ 代码缺陷**：若真实观点质量不佳（套话、反驳无力），那是 prompt 调优问题，记录到 T9 待调优清单，**不要**为了"看起来更好"去改确定性裁决逻辑或放宽 evidence 校验。
- **真实暴露的确定性 bug 必须 TDD 修**：先加失败测试复现，再修，保证回归。
- **联调用真实 key 全程不入库代码/不进提交**；样本脱敏后才入文档。
- 真实数据回测注意复权口径（方案 06 已要求实测确认腾讯直连源复权方式）；口径不符会让回测结论失真。
