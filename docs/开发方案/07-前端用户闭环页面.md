## 1. 背景与现状

前端 `apps/agent-office`（React + Vite，单文件 `main.tsx` 为主 + 视图模块）当前导航共 11 项（`main.tsx:117-127`）：

| 导航 id | 标签 | 当前状态 |
| --- | --- | --- |
| overview | 总览 | **真实数据**（DashboardService 聚合） |
| portfolio | 持仓监控 | 占位/静态 |
| watchlist | 观察池 | 部分真实（观察池分组 pools 已接） |
| recommendation | 推荐决策 | 占位/静态 |
| risk | 风险中心 | 占位/静态 |
| agent | Agent 运行 | 占位/静态 |
| report | 中文报告 | 占位/静态 |
| memory | Finance Memory | 占位/静态 |
| data | 数据同步 | **真实数据**（dataSyncView） |
| tasks | 任务监控 | **真实数据**（taskMonitorView，本次新增） |
| model | 模型配置 | **真实数据** |

已确立的前端工程模式（必须沿用）：

- 视图逻辑拆为纯函数模块（如 `taskMonitorView.ts`：normalize → model → format 函数），`main.tsx` 只做组件渲染。
- 每个视图模块配 node 脚本测试：`apps/agent-office/scripts/test-*.mjs`（无测试框架，直接断言）。
- API 封装集中在 `src/api.ts`，基址 `VITE_FINANCE_AGENT_API_BASE`。
- 聊天窗口（SSE）已可用。

后端可复用资产：`DashboardService`（含 `classify_watchlist_pool` / `watchlist_pool_definitions`）、`FinanceAgentInterface`（报告读取、Workflow 审计查询）、`MemoryService`、决策/提醒/触发事件等表均已有数据。

**缺口**：用户能"运维数据"但看不到"金融结论"——报告、推荐榜、持仓、提醒、记忆 7 个页面无真实数据，私人金融助手的展示闭环断裂。

## 2. 目标与非目标

**目标**

按价值排序落地 6 个页面的真实数据版：

1. **report 中文报告**（最高价值：报告是系统全部能力的汇聚出口）
2. **recommendation 推荐决策**（推荐榜 + 风险反驳 + 用户反馈入口）
3. **portfolio 持仓监控**
4. **risk 风险中心 / 提醒中心**（合并触发事件与风险发现）
5. **agent Agent 运行**（Workflow 审计状态）
6. **memory Finance Memory**（记忆时间线）

**非目标**

- 不引入路由库/状态管理库/组件库（维持现有单页 + tab 模式，避免技术栈漂移）。
- 不做图表库新增（ECharts/TradingView 接入属后续体验增强，本方案以信息完整为先）。
- K 线图、因子雷达图等可视化不在本批次。

### 3.2 前端页面规格

每页一个视图模块 + 一个 node 测试，模式抄 `taskMonitorView.ts`：

**P1 report 报告页**
- 左列表（时间倒序、workflow 类型徽标、裁决摘要、复核状态色点：通过绿/驳回红/待人工黄/未复核灰）。
- 右详情：Markdown 渲染（新增轻量依赖 `marked` 或手写有限渲染器）。**T3 实施决策（2026-06-13）**：当前前端依赖集中在 React/Vite/lucide，执行环境网络受限，本轮不新增 npm 依赖；采用内置有限 Markdown 渲染器，仅开放标题、列表、引用、表格、粗体和行内代码，并先做 HTML 转义，脚本测试覆盖 `<script>` 转义。
- 详情顶部固定"结论 → 证据 → 风险反驳 → 行动 → 确认边界"锚点导航（与 Hermes skill 输出规则一致）。

**P2 recommendation 推荐页**
- 推荐运行选择器（最近 N 次，按市场分组——A 股与数字货币分 tab，**不混排**）。
- 排序表：评分、动作徽标、置信度、信号方向、风险计数；展开行显示评分拆解（分组贡献）与风险反驳全文。
- 每行操作：「查看报告」跳 report 页定位；「反馈」弹窗（accepted/rejected/modified/deferred + 备注）提交到反馈 API。
- 顶部显著展示 `avoid_pool_excluded` 摘要（"本次运行剔除回避池 N 项"），点开看明细——透明性要求。

**P3 portfolio 持仓页**
- 组合卡片（市值、成本、盈亏、现金）+ 持仓表（盈亏、最新信号方向、风险标记、最近建议动作）。
- 集中度提示条（行业/单标的占比超阈值标黄）。

**P4 risk 提醒中心**
- 两区：未读提醒（monitoring_alerts）与触发事件流（assistant_trigger_events，含 agent 处理状态——pending/dispatched/已生成 workflow_run 可跳转）。
- 风险发现列表（risk_findings 最近 N 条，按严重度分色）。

**P5 agent 运行页**
- Workflow 运行表：状态、耗时、触发来源、圆桌观点 `generated_by` 占比（模型/规则）、复核状态；点击展开 node_trace 与 tool_calls 摘要。

**P6 memory 记忆页**
- 按资产筛选的时间线：入池原因 → 每日关注 → 用户反馈 → 复盘结论，每条带置信度与衰减状态徽标。

### 3.3 工程约束

- `main.tsx` 已 1400+ 行新增，继续膨胀不可持续：本方案各页组件**必须**拆为独立 `src/pages/*.tsx` 文件（React 组件可以拆文件，不算引入新框架；视图纯函数仍在 `*View.ts` 模块）。`main.tsx` 只保留导航与页面挂载。
- 轮询节奏：报告/推荐/持仓 60s，提醒中心 30s，复用任务监控页现有 `setInterval` + silent refresh 模式。
- 所有新 API 调用集中进 `api.ts`，错误统一 toast（现有模式）。

## 6. 风险与注意事项

- **不要给占位页编造数据**：接不到的字段显示"—"并标注来源缺失，宁缺毋假（事实优先原则在 UI 同样适用）。
- 报告 Markdown 来自后端模板，渲染前仍做转义白名单（标题/列表/表格/粗体足够，禁 script/iframe/原始 HTML）。
- 推荐页的动作徽标文案必须带"建议/候选"字样（如"候选买入"），不得出现"买入"裸文案——不自动交易的表达边界。
- T7 重构是纯移动：用 git diff 确认无逻辑变更，前后构建产物行为一致。
