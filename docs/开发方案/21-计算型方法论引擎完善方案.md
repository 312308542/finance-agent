# 方案 21：计算型方法论引擎完善

> 优先级：P1 ｜ 批次 7 补强专项 ｜ 前置阅读：`20-金融分析方法论技能库.md`
> 本方案承接方案 20 中被后置的主观结构类方法论，目标是在不新增外部依赖的前提下，先提供 A 股可用、可审计、可降级的确定性基线引擎。

## 1. 背景

方案 20 已完成方法论 skill 加载、P1/P2 方法论和部分 P3 适配器，但 harmonic、elliott-wave、smc 第一版仅保留 skill 与引擎依赖声明。这个状态能守住“LLM 不自己算结构”的红线，但对实际选股帮助不足。

> 2026-07-04 收口说明：本方案交付的是 structural-lite v1 工程骨架。总负责人复核发现的判别力缺陷、噪声地板、as-of 语义和业务接入，已由方案 22 升级为 structural-lite v2 后完成；后续引用 harmonic/elliott-wave/smc 时以方案 22 的 v2 schema、调度入库和前端证据卡片为准。

总负责人要求本轮集中补齐一个“真实可用，符合实际使用”的方法论引擎。参考 `D:\Code\aiAgents\Vibe-Trading` 后，值得借鉴的是工程路径，而不是直接照搬依赖：

- 先从 OHLCV 中确定性提取 swing 结构。
- 再在 swing 上识别结构事件、谐波候选或波浪候选。
- 输出结构化 evidence、置信度、失效条件和禁令，供圆桌 skill 解读。

## 2. 目标

本方案目标：新增一套 A 股优先、OHLCV 驱动、低依赖的结构方法论引擎，让技术分析师节点能引用真实可计算的结构证据，而不是让模型凭文字想象。

第一版上线范围：

| 引擎 | 本轮目标 | 输出定位 |
| --- | --- | --- |
| Swing 结构基座 | 提取交替高低点、趋势段和最近结构状态 | 供下游 harmonic/SMC/Elliott 复用 |
| Harmonic-lite | 基于 XABCD 五点和 Fibonacci 容差识别候选形态 | 只作为潜在反转候选，不直接改动作 |
| SMC-lite | 识别 BOS、CHoCH、公允价值缺口 FVG | 输出结构事件和风险提示 |
| Elliott-lite | 识别有限的 5 浪推动 / ABC 调整候选 | 低置信度只提示结构不清晰 |
| 统一 payload | 所有引擎输出统一 schema、evidence_id、red_lines | 便于入库和圆桌引用 |

## 3. 非目标

- 不引入真实交易、自动下单或券商写接口。
- 不让 LLM 计算 swing、浪型、XABCD、BOS/CHoCH 或 FVG。
- 不把谐波/波浪/SMC 作为买卖动作的决定性依据，只作为技术结构证据。
- 不在本轮安装 `pyharmonics`、`smartmoneyconcepts`、`czsc` 等新依赖；成熟库增强保留扩展点。
- 不处理数字货币链上/DeFi 方法论，D-009 仍按“先专注 A 股”执行。

## 4. 设计原则

### 4.1 准确性边界

结构类方法论天然有主观性，因此第一版采用“宁可少报，不强报”的策略：

- Swing 点必须交替，连续同类点只保留更极端值。
- 每个结构事件必须包含参与点位和输入区间。
- 每个候选必须有 `confidence` 和 `caveats`。
- 置信度低于阈值时，Elliott-lite 只返回 `status=insufficient_structure`，不输出浪型观点。

### 4.2 红线

- 计算归确定性引擎，解读归 skill。
- LLM 不得修改 `total_score`、动作枚举、风险标记或信号方向。
- 引擎输出必须可审计：`schema_version`、`engine`、`engine_version`、`evidence_id`、输入起止时间、bar 数量必须齐全。
- 所有结构结论都必须来自入库 K 线，不允许 Agent 层临时外呼行情。

## 6. 任务拆解

### T1：Swing 结构基座

- 先写失败测试：固定 OHLCV 样例应提取交替 swing 点，连续同类点只保留更极端值。
- 实现 `StructuralMethodologyAdapter.compute_swings()`。
- 输出 `SwingPoint` 与 `SwingStructureResult`，包含趋势段、最近高低点、evidence_id。

### T2：Harmonic-lite

- 先写失败测试：构造一个近似 Gartley 的 XABCD 序列，断言输出形态候选、方向、比例、置信度和失效条件。
- 实现 `compute_harmonic()`，复用 swing 结构，容差默认 0.12。
- 输出 `schema_version=harmonic_lite_v1`，禁止声称外部 `pyharmonics` 已启用。

### T3：SMC-lite

- 先写失败测试：构造突破前高、跌破前低和三根 K 线 FVG，断言输出 BOS/CHoCH/FVG 事件。
- 实现 `compute_smc()`，只覆盖 BOS、CHoCH 和 FVG，不输出订单块的强结论。
- 输出 `schema_version=smc_lite_v1`，明确 caveat：订单块/流动性池为后续成熟引擎增强。

### T4：Elliott-lite

- 先写失败测试：构造清晰的 5 浪推动和弱结构样例，断言清晰样例输出候选，弱结构样例拒绝高置信度观点。
- 实现 `compute_elliott()`，只输出候选浪型和置信度，不给绝对计数结论。
- 输出 `schema_version=elliott_lite_v1`，低于阈值返回 `insufficient_structure`。

### T5：统一 payload 与 skill 接入说明

- 所有输出包含 `engine=finance-agent-structural-lite`、`engine_version`、`red_lines`、`caveats`。
- 更新 harmonic / elliott-wave / smc skill 的输入和禁令说明。
- 防回归测试确认 payload 中保留红线，skill 不要求 LLM 自算结构。

### T6：文档同步与验收

- 更新本方案进度表、方案 20、方案 00 总览。
- 运行专项测试和相关方法论测试。
- 若全量测试成本可控，运行全量 `pytest -q`；否则记录已运行的专项命令和未跑原因。
