# 方案 09：轻量回测与绩效验证（M3 欠账）

> 优先级：P2 ｜ 批次 4 ｜ 依赖：方案 05（策略权重外置后回测才有对象）
> 前置阅读：`00-总体规划与执行约定.md`

## 1. 背景与现状

这是本轮方案体系审查中发现的**系统性漏项**：回测在三处被项目目标文档承诺，但代码中完全不存在，且 9 条 O 优化主线均未覆盖——

- 《项目计划》§3.3 输出原则：每条建议必须包含"支持因子和信号……回测结果"；§7.2/7.3 指定 `bt` 做组合回测、`quantstats` 做绩效分析；M3 里程碑列了"bt 组合回测适配器、quantstats 绩效报告适配器、BacktestResult 和 PerformanceReport"。
- §17 测试计划有专门的"回测测试"小节（固定策略+固定数据生成稳定收益/回撤/胜率，结果必须引用数据版本和信号版本）。
- README 中期路线：完善推荐流水线的"回测摘要"。

**代码现状（2026-06-11 核实）**：`src/finance_agent/backtesting/` 目录不存在；全仓库无 `import bt`、无 `quantstats` 引用；`pyproject.toml` 是否声明这两个依赖需开工时确认。推荐报告的证据链目前只有因子、信号、风险，没有任何历史验证维度。

**定位澄清**：这不是"量化模型研究 TODO"（ML 打分、IC/RankIC、风格中性化——那些仍然延后）。这是更基础的一层：**当前透明规则评分策略在历史上的表现如何**，是推荐可信度的底线证据。

## 2. 目标与非目标

**目标**

1. `bt` / `quantstats` 适配器落地，输出统一 `BacktestResult` / `PerformanceReport`（领域协议见 `docs/领域协议.md`，不泄漏库内部对象）。
2. 内置一个可回测的基准策略：`factor_score_topn`（按 `asset_scores` 取 TopN、定期再平衡），对接方案 05 的策略权重。
3. 回测结果落库并进入推荐报告的证据链（"该策略近 N 年回测：年化、最大回撤、夏普"）。
4. CLI 与调度入口（低频，如每周）。

**非目标**

- 不做参数搜索/优化（vectorbt 仍排除，见项目计划 §7.4）。
- 不做逐笔交易级模拟；周期收益维度即可（quantstats 的胜率口径限制在文档与报告中注明）。
- 不让回测结果直接改变评分——它是证据，不是因子。

## 3. 技术方案

### 3.1 模块结构

```text
src/finance_agent/backtesting/
  __init__.py
  adapters.py        # BtBacktestAdapter / QuantstatsPerformanceAdapter
  strategies.py      # factor_score_topn 策略构造（输入：universe、strategy_id、topn、再平衡频率）
  service.py         # BacktestService：取历史评分与行情 -> 跑回测 -> 落库
```

数据输入：`market_bars`（已有 10 年日 K）+ 历史 `asset_scores`（注意：评分历史从评分服务上线才开始积累，早期回测可用"按当前权重对历史因子重算评分"的近似模式，模式必须在结果 payload 标注 `score_mode: replayed|historical`）。

### 3.2 落库

新增迁移 `20260614_0019_create_backtest_tables.py`（版本号顺延，若方案 08 已用 0018）：

- `backtest_results`：backtest_id、market、strategy_id、universe_id、时间区间、再平衡频率、`metrics`(JSONB：CAGR/最大回撤/夏普/Sortino/换手)、`data_versions`(JSONB：bars 水位、评分模式、规则版本——满足 §17 可复现要求)、status、created_at。
- 绩效明细（月度收益表、回撤序列）放 payload JSONB，不另建表。

### 3.3 接入证据链与报告

- `RecommendationService` 写推荐时附最近一次同策略 `backtest_result` 引用（evidence 模式，backtest 缺失时标注"无回测证据"并降低报告中的确定性措辞——不阻塞推荐）。
- 报告模板"证据"section 增加回测摘要行；前端 recommendation 页（方案 07）展开行透出。

### 3.4 入口

- CLI：`finance-agent backtest run --strategy factor_score_topn --universe <id> --strategy-id <scoring strategy> --years 5`（命令形态与项目计划 §12 草案对齐）。
- 调度任务：`analytics.backtest.weekly`（周末跑，依赖收盘任务成功，按方案 02 模式接入）。

## 6. 风险与注意事项

- `bt`/`quantstats` 维护不活跃，是已知技术债：适配器层必须把两库完全隔离在 `adapters.py` 内，领域对象不出现任何库类型，将来可换引擎。
- `replayed` 评分模式有前视偏差风险（用今天的权重回放历史）：结果 payload 必须显著标注模式，报告措辞用"模拟回放"而非"历史实盘"。
- quantstats 胜率是周期收益维度（项目计划 §7.3 已警示），报告字段命名用 `period_win_rate`，避免误读为逐笔胜率。
- Windows 上 `bt` 依赖链如果安装失败，降级路径：先只上 quantstats 绩效（输入为 TopN 组合的简单等权收益序列，pandas 自算），bt 适配器单独排期——不要让依赖问题阻塞证据链接入。
