# 方案 05：推荐链路质量收尾（O6 收尾）

> 优先级：P1 ｜ 批次 3 ｜ 依赖：无（可与批次 2 并行）
> 前置阅读：`00-总体规划与执行约定.md`

## 1. 背景与现状

已有资产：

- `src/finance_agent/pipelines/recommendation.py`：`UniverseRecommendationPipeline` 已支持 `candidate_source="technical_screening_pool"`——配置后优先使用最近技术初筛通过项（`prefer_technical_screening_members`），runtime 配置已启用。
- `src/finance_agent/application/data_production_service.py`：`ProductionUniverseService.merge_universes`（同市场多候选池按来源权重合并去重）与 `AvoidPoolPolicy`（按资产状态/ST/退市/高风险生成 `included=false` 回避池）均已实现，并有 CLI：`data production merge-universe`、`data production rebuild-avoid-pool`。
- `ScoringService` 按市场写死了 A 股/数字货币两套权重；`ScreeningService` 第一版硬过滤可用。
- 研究跟踪池已有入池阈值（`min_total_score`/`min_confidence`）、3 天有效期与过期清理（`watchlist_service.expire_research_pool_items`）。

**缺口**（`docs/优化版本进度跟踪表.md` O6 自报）：

1. **推荐运行入口不引用回避池**：回避池建出来了，但 `UniverseRecommendationPipeline.run` 不剔除回避池成员——被标记规避的标的仍可能进推荐榜。
2. **合并池没接推荐入口**：多来源合并池只能 CLI 手动产出，调度的推荐任务用的还是单一候选池。
3. **策略权重不可配置**：短线/波段/防守等策略没有独立权重，`docs/因子规格配置.md` 已有设计但未实现到评分层。
4. 推荐重复入池没有冷却期（同一标的被反复推荐反复入研究池）。

## 2. 目标与非目标

**目标**

1. 推荐流水线运行前强制执行回避池剔除，剔除行为可审计。
2. 调度的推荐任务支持"先合并多池 → 再剔除回避池 → 再跑流水线"的标准前置链。
3. 评分权重策略化：数据库表 + CLI 管理，预置 4 套策略。
4. 研究池入池冷却期：被移出后 N 天内不因同类推荐自动重新入池。

**非目标**

- 不引入机器学习打分（仍属第一版后 TODO）。
- 不改透明评分的计算公式本身，只把权重外置。

## 3. 技术方案

### 3.1 回避池接入推荐入口

`UniverseRecommendationPipeline.run` 新增参数 `avoid_universe_id: str | None`：

- 在 `ensure_single_market_universe` 之后、技术初筛优先逻辑之前，读取回避池成员（`included=false` 语义按 `AvoidPoolPolicy` 既有产出），从 `members` 中剔除。
- 剔除结果写入运行审计：`recommendation_runs` 的 payload 增加 `avoid_pool_excluded`（数量 + asset_id 列表 + 各自剔除原因，原因来自回避池成员 payload）。
- 市场校验：回避池 market 必须与候选池一致，否则抛错（沿用单市场校验风格）。
- `sync_config.py` 推荐任务参数增加 `avoid_universe_id`（默认指向 `data production rebuild-avoid-pool` 的默认输出池 ID；先盘点该 CLI 当前生成的池 ID 命名再固化）。

### 3.2 合并池前置链

不把合并逻辑塞进流水线，而是调度层组合既有能力：

- 新增 `sync_task_type = analytics.universe.merge`：调 `ProductionUniverseService.merge_universes`，参数 `source_universe_ids`、`target_universe_id`、来源权重。
- 调度依赖：`analytics.universe.merge` → after_success → `analytics.recommendations.*`（推荐任务的 `universe_id` 指向合并产物）。
- 回避池重建任务同理：`analytics.universe.rebuild_avoid_pool`，挂在风险数据刷新任务之后。

### 3.3 策略权重配置中心

**存储**：新增迁移 `20260612_0017_create_scoring_strategy_tables.py`，表 `scoring_strategies`：

| 列 | 说明 |
| --- | --- |
| strategy_id (PK) | 如 `strategy:ashare:balanced_growth` |
| market | ashare / crypto_spot / crypto_future |
| name / description | 中文名与说明 |
| group_weights (JSONB) | 因子组权重，结构与 `ScoringService` 现有内置权重一致 |
| missing_penalty (JSONB) | 缺失惩罚配置 |
| status | active / draft / archived |
| created_at / updated_at | |

**预置策略**（迁移内置 seed 或 CLI init）：

- A 股：`balanced_growth`（现状权重平移）、`short_swing`（技术/资金流加权）、`defensive`（低波动/质量加权）。
- 数字货币：`crypto_swing`（现状权重平移）。

**评分层接入**：`ScoringService` 增加 `strategy_id` 参数；未指定时回退现有内置权重（保证全部既有测试不破）。`asset_scores` 落库 payload 记录 `strategy_id` 与权重快照（评分可复现）。

**CLI**：`finance-agent data strategy list/show/set/init`（归到现有 `data` 命令组；`set` 只允许改 draft，激活时校验权重和为 1±0.001）。

**调度透传**：推荐任务参数增加 `strategy_id`，经 `BaseDataScheduler` 透传到流水线 → 评分。

### 3.4 研究池入池冷却

- `watchlist_service` 新增检查：`research_intake` 前查询该资产最近一次 `removed/expired` 的研究池事件（`watchlist_item_events`），若在冷却窗口内（默认 7 天，参数化）则跳过并写 `recommendation_skipped` 审计（复用 `personal_assistant.py` 现有 skip 事件模式，reason=`cooldown`）。

验收标准：

- 回避池中的 ST/退市标的不会出现在新推荐运行结果中，且剔除原因可查。
- 同一候选池用 `balanced_growth` 与 `short_swing` 两套策略评分，排序产生可解释差异，评分 payload 含权重快照。
- 被移出研究池的标的 7 天内不自动重新入池。

## 6. 风险与注意事项

- `ScoringService` 是推荐链路核心，权重外置必须保证"未指定 strategy_id 时行为与现状逐字节一致"——用既有评分测试做金标准回归。
- 回避池剔除发生在技术初筛优先**之前**：技术初筛通过但在回避池里的标的必须被剔除（安全优先于信号）。
- 合并池任务的来源池可能由不同任务刷新，注意 after_success 依赖不要形成环（调度器已有依赖触发，配置时手工画一遍依赖链）。
