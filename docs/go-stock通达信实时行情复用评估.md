# go-stock / gotdx 通达信行情复用评估

## 结论

`go-stock` 可以作为 A 股持仓、观察池和最近推荐标的的低延迟行情 PoC 参考，但不能直接宣称为“交易所级实时行情”。`gotdx` 使用通达信 TCP 主行情协议，采用同步请求/响应和节点自动测速，适合把当前 5 分钟一次的全市场 HTTP 快照替换为小范围秒级轮询；它没有发现 Push、Subscribe 或 WebSocket 推送语义，也没有提供完整 Tick 序号、交易所时间戳和不丢包保证。

当前建议保留两条数据链路：

```text
高速链路：gotdx 行情网关 -> 重点标的快照/异动 -> 确定性持仓风控 -> 提醒
慢速链路：AKShare/其他 HTTP Provider -> 日 K、基本面、资金流、新闻 -> 推荐和换仓分析
```

推荐 Agent、Hermes 和联网复核只能消费已经通过新鲜度和质量门禁的数据，不能绕过行情网关直接把网页结果当作风控事实。

## 本次验证

验证日期：2026-07-19（北京时间，非交易日）。验证环境：Windows amd64、Go 1.26、`go-stock` 当前 `dev` 分支。

| 验证项 | 结果 | 说明 |
| --- | --- | --- |
| `go-stock/backend/data` TDX 相关测试 | 通过 | `go test ./backend/data -run 'TestTdxKLineApi...'`，包含集合竞价、日 K、1/5/15/30/60 分钟线 |
| `gotdx` 快照集成测试 | 通过 | `GOTDX_INTEGRATION=1 go test github.com/bensema/gotdx -run Test_tdx_GetSecurityQuotes -count=5` |
| 快照请求耗时 | 约 0.17～0.51 秒/次 | 连续 5 次均成功，整体测试耗时约 11.4 秒 |
| 服务端时间 | 返回 `15:33:10.194` | 周末仍返回最近交易日快照，字段只有时分秒，没有日期 |
| 五档盘口 | 可用 | `BidLevels`、`AskLevels` 各 5 档，同时有价格和委托量 |
| 分时/分笔能力 | 可用 | 通过标准协议接口读取，但仍是轮询响应 |

这组结果证明“请求低延迟、节点可连接”，不能证明“每次都是最新行情”。接入时必须把服务端时间、接收时间和交易日联合判断，不能仅使用本机请求完成时间。

## 可复用能力

### 直接依赖

- 直接依赖 MIT 许可证的 `github.com/bensema/gotdx`，不复制 `go-stock` 的 GPLv3 应用业务代码。
- 使用 `WithAutoSelectFastest(true)`、超时和有限重试；连接失败时断开旧连接并重连。
- 对沪深北市场代码做统一路由，保留 `SH/SZ/BJ` 市场信息，不通过首位数字猜测后再丢弃市场。

### 借鉴适配器设计

- 主行情、MAC、MAC 扩展行情分开管理，并分别加锁，避免一个连接故障拖垮其他市场。
- 原始通达信结构先转换成平台统一快照，再交给持仓监控和触发器。
- `StockUnusual`、`StockAuction`、`MACMarketMonitor` 作为全市场候选事件源；候选事件进入观察池后，再对重点标的做深度快照。
- 连接节点、请求耗时、重试次数和返回条数写入运行指标，不能只记录“任务成功/失败”。

### 不直接复用

- `go-stock` 的 Wails/Vue、SQLite/GORM、5 分钟分笔缓存和新浪/腾讯/东方财富网页接口不作为 `finance-agent` 的事实层实现。
- 分笔缓存只适合页面展示，不能作为卖出信号的最新价格来源。
- 不把 TDX 日 K 结果写入当前 `market_bars` 的收盘生命周期任务；盘中分钟线和日 K 仍是两个不同数据域。

## finance-agent 接入边界

### 高速链路只覆盖重点标的

第一阶段只轮询：

1. 当前持仓；
2. 用户观察池；
3. 最近一次推荐且仍然有效的标的。

不对全市场约 3,000 多只股票做秒级轮询。全市场异动优先使用 `StockUnusual`/`MACMarketMonitor` 这类服务端筛选接口，发现候选后再加入重点集合。

### 统一快照最小字段

现有 `realtime_quote_snapshots` 可以承载基础价格，但 TDX 接入前必须在 `payload` 中至少保存：

```json
{
  "source": "gotdx:tdx_main",
  "server_time": "15:33:10.194",
  "received_at": "2026-07-19T13:43:40.419Z",
  "freshness_ms": 0,
  "provider_latency_ms": 180,
  "node": "host:7709",
  "sequence": null,
  "quality_status": "after_hours_snapshot",
  "bid_levels": [{"price": 7.02, "volume": 68}],
  "ask_levels": [{"price": 7.06, "volume": 1}]
}
```

其中 `server_time` 只有时分秒时，`quality_status` 不能直接标为 `available`。必须结合交易日历和本地接收时间推断日期；日期无法确认时只能标为 `stale` 或 `after_hours_snapshot`，禁止触发秒级卖出信号。

### 风控触发规则

- 确定性规则直接读取最新且质量通过的 TDX 快照：跌破止损、持仓收益回撤、盘口流动性骤降、服务端时间落后。
- 推荐、换仓和新闻解释仍走慢速链路，并要求引用日 K、基本面、资金流和联网检索证据。
- 快照过期、连续缺口、节点切换或数据源冲突时，触发“数据不可用”告警，不生成确定性卖出结论。
- 任何“卖出信号”都必须区分：`market_data_signal`（行情规则）和 `agent_advice`（Agent 建议），不能混为自动交易指令。

## 推荐的实施顺序

### 阶段 0：不改业务语义

- 新增独立 Go 行情网关 PoC，只提供只读 HTTP 或 Redis Streams 输出。
- 不替换当前 AKShare 任务，不改变推荐、风险中心和持仓监控的现有数据库契约。
- 记录连续运行、延迟、服务端时间、节点和缺口指标。

### 阶段 1：接入重点标的快照

- 将网关输出映射到 `realtime_quote_snapshots`，`source` 使用稳定值 `gotdx:tdx_main`。
- 只在交易窗口运行 1～3 秒轮询；收盘后停止高速轮询，保留最多两次补采。
- 让现有盘中触发器读取同一张快照表，并增加 freshness/quality 门禁。

### 阶段 2：接入异动候选

- 周期读取 `StockUnusual` 或 `MACMarketMonitor`，按“事件时间 + 股票 + 事件类型 + 原始摘要”去重。
- 事件只进入观察池/候选池，不直接产生买入或卖出动作。
- 对候选标的追加盘口、分时、分笔复核，并记录缺失和节点切换。

### 阶段 3：连续运行验收

至少完成 5 个交易日连续运行后，才允许将 TDX 作为持仓风控主源。验收指标：

- 交易窗口请求成功率 >= 99%；
- 重点标的快照端到端延迟 P95 <= 3 秒；
- 服务端时间可解析率 >= 99%；
- 断线重连后 3 个轮询周期内恢复；
- 节点切换不产生重复卖出事件；
- 任何数据质量降级都能在风险中心展示并留痕。

## 许可证和运行风险

`gotdx` 是 MIT，可以作为独立依赖；`go-stock` 应用本身为 GPLv3，不能直接复制其业务源码进入本项目。通达信协议属于第三方服务，节点地址、字段含义和可用性可能变化，生产接入前需要保留可切换的 AKShare/腾讯等降级源，并通过质量门禁阻止陈旧快照进入风控。

## 下一步决策

下一步应实现“独立 Go 行情网关 PoC + `gotdx` 快照质量测试”，而不是立即改写当前全市场 AKShare 采集器。PoC 连续运行达到上述验收指标后，再把 `gotdx:tdx_main` 接入重点标的持仓监控；日 K、基本面和 Agent 推荐链路继续沿用慢速数据源。
