# UI/UX 设计规范

本文档基于本地 `ui-ux-pro-max` skill 生成的设计系统，并结合本项目的金融工作台目标做了项目化调整。

适用范围：

- `web/` 前端 Dashboard
- CLI 输出中的报告排版
- 持仓监控、私人观察池、推荐建议、风险确认、证据查看、决策日志和订单草案等关键交互

## 1. 设计目标

- 让金融小白能看懂结论。
- 让专业用户能快速看细节。
- 让高风险动作无法误触。
- 让图表、证据、推荐、风险彼此联动。
- 让持仓、观察池、提醒、建议、决策日志和复盘形成闭环。
- 让界面像专业金融工作台，而不是营销页。

## 2. 视觉方向

### 2.1 总体风格

- 数据密集。
- 操作导向。
- 低噪声。
- 结构清晰。
- 视觉克制。

### 2.2 推荐模式

- 默认采用深色工作台风格。
- 保留浅色阅读模式作为可选项，但不作为主视觉。
- 避免单一蓝色主导全站。
- 蓝色只用于链接、选中态和中性信息。
- 风险、盈利、确认、警示使用红、绿、琥珀分层表达。

### 2.3 色彩原则

建议主调：

- 背景：深黑或近黑中性底色。
- 主信息：浅灰白文字。
- 正向状态：绿色。
- 风险提示：红色。
- 注意/待确认：琥珀色。
- 数据高亮：蓝色仅做辅助。

禁止：

- 大面积渐变装饰。
- 蓝色一把梭。
- 霓虹过亮。
- 纯装饰性光球、光斑、bokeh。

## 3. 布局原则

- 首页不是营销页，不做大 HERO。
- 默认首屏是“今日概览 + 风险摘要 + 推荐动作 + 待确认订单”。
- 页面使用稳定网格，不让卡片随内容乱跳。
- 单页信息密度高，但保持分区清楚。
- 不做卡片套卡片。
- 控制边框、阴影和留白，避免“又大又空”。
- 使用 12 列或等价响应式网格。
- KPI 卡片、图表和表格要稳定占位，避免加载后跳动。
- 长表格和 Agent 日志超过 100 行时必须虚拟化。

推荐布局：

- 顶部：全局状态条、市场状态、账户状态、告警。
- 中部左侧：核心图表。
- 中部右侧：推荐、风险、证据。
- 底部：持仓表、事件时间线、回测摘要。

## 4. 页面设计

### 4.1 首页总览

首屏必须展示：

- 组合当前风险等级。
- 持仓异常和实时/定时提醒。
- 私人观察池启动条件命中数量。
- 今日推荐动作总览。
- 待确认订单草案数量。
- 账户盈亏和回撤。
- 关键资产分布。
- 数据源健康状态。
- 自动刷新状态。
- `partial/stale/unavailable` 数据提示。

### 4.2 持仓体检

重点不是报表，而是“体检结果”。

- 持仓集中度。
- 浮盈浮亏。
- 杠杆和爆仓风险。
- 行业暴露。
- 持有理由和反方观点。
- 是否需要减仓、加仓、卖出候选或换股比较。

### 4.3 私人观察池

观察池页面展示主 Agent 长期维护的潜力标的，不等同于一次推荐候选池。

- 关注理由。
- 来源推荐或来源事件。
- 观察条件。
- 启动条件。
- 失效条件。
- 风险等级。
- 下次复核时间。
- 移除原因。

### 4.4 信号中心

信号中心分层展示：

- 技术信号。
- 基本面信号。
- 合约信号。
- 事件信号。
- 组合信号。

每层都需要：

- 分数。
- 方向。
- 置信度。
- 时间戳。
- 解释摘要。

### 4.5 推荐页

推荐必须是“可执行建议”而不是大段文字。

推荐卡片固定包含：

- 动作。
- 建议仓位。
- 支持信号。
- 反方观点。
- 风险等级。
- 证据入口。
- 对当前持仓的影响。
- 是否建议加入观察池或触发换股比较。

禁止：

- 大标题营销页布局。
- 紫色 AI 渐变作为主视觉。
- 只给结论不给反方观点。

### 4.6 风险中心

风险中心要像预警面板。

- 严重程度排序。
- 风险类型标签。
- 可能亏损场景。
- 建议动作。
- 是否需要二次确认。

### 4.7 决策日志与复盘

决策日志页面用于解释系统曾经建议过什么、用户是否采纳、后续复盘如何评价。

- 系统建议。
- 用户动作。
- 关联持仓或观察项。
- 证据和风险引用。
- 复盘结论。
- 记忆写入摘要。

### 4.8 订单草案页

订单草案页面必须极度清晰：

- 买卖方向。
- 数量。
- 限价。
- 预计手续费。
- 止损止盈。
- 风险阻断原因。
- 二次确认按钮。
- loading、success、error 提交状态。
- 过期状态。
- 风控阻断状态。

禁止：

- 默认隐藏关键价格。
- 让用户不知道会不会下单。
- 把确认按钮和取消按钮做成近似危险布局。

订单确认弹窗必须包含：

- 订单方向、数量、价格。
- 来源推荐。
- 风险摘要。
- 预计费用。
- 止损止盈。
- 明确“确认后才会提交”的提示。
- 清晰关闭按钮。
- focus trap 和键盘可操作。

## 4.9 页面级 Override

页面实现时按以下优先级处理：

1. 本文档。
2. `docs/前端与体验设计/界面体验调研记录.md` 中的采纳决策。
3. `docs/前端与体验设计/ui-ux-pro-max-output/design-system/hermes-finance-agent/pages/[page].md`。

注意：自动 page override 中出现 landing page、portfolio grid、vibrant block 等模式时，不直接采纳。

## 5. 组件规范

### 5.1 基础组件

- 使用 Ant Design 做表格、表单、弹窗、标签、布局。
- 图标优先用 Lucide 或同一套 SVG 图标。
- 所有可点击元素都有 `cursor:pointer`。
- 所有可交互元素都有明显 hover 和 focus 状态。

### 5.2 业务组件

必备组件：

- `RiskTag`
- `SignalScore`
- `RecommendationPanel`
- `WatchlistItemPanel`
- `DecisionLogTimeline`
- `MemorySummary`
- `WorkflowEventTimeline`
- `OrderConfirmModal`
- `EvidenceDrawer`
- `PortfolioHealthCard`
- `PositionTable`
- `KlineChart`
- `DrawdownChart`
- `AllocationHeatmap`

### 5.3 表格规范

- 表格默认可排序、可过滤。
- 关键字段固定列。
- 长文本折叠显示。
- 数值列右对齐。
- 风险列颜色明确但不刺眼。

## 6. 图表规范

优先使用的图表：

- K 线图。
- 收益曲线。
- 回撤曲线。
- 资产分布图。
- 相关性热力图。
- 风险雷达图。
- 区间分布箱线图。
- 资金流向图。

图表规则：

- 图表和表格必须能互相联动。
- 鼠标悬停要显示明确数值。
- 图例必须可读。
- 颜色不能只靠色相区分。
- 所有图表需要无障碍替代表格或摘要。
- K 线图最多默认展示 500 根可见 K 线，超出要分页或缩放。
- K 线涨跌不能只靠红绿，必要时用实心/空心或边框差异。
- 热力图必须有数值 legend。
- 多 KPI 对阈值比较优先用 bullet chart，而不是堆很多仪表盘。

## 7. 交互规范

- 刷新必须有明确 loading 状态。
- 超过 300ms 的异步操作必须显示 skeleton、spinner 或按钮 loading。
- 数据过期必须标注 `stale`。
- 失败必须说明原因，而不是静默空白。
- 空状态必须说明原因和下一步。
- 提交成功必须有 toast 或状态提示。
- 推荐卡片可展开细节。
- 证据抽屉可从任意结论一键打开。
- 订单草案必须二次确认。
- 高风险动作必须弹出更强提示。

## 7.1 React 实现规则

- 路由页懒加载。
- K 线、热力图、回测报告等重组件懒加载。
- 长列表和大表格使用虚拟化。
- 表格筛选、排序、聚合等昂贵计算用 memo 化。
- 能从服务端数据推导的状态不要重复存本地 state。
- 复杂交互状态使用 reducer。
- Modal 打开后要管理 focus，关闭后返回触发元素。
- 使用 TanStack Query 管理服务端状态、缓存、刷新和错误。

## 8. 无障碍规范

- 文本对比度至少 4.5:1。
- 键盘可完整操作。
- focus 状态必须可见。
- 尊重 `prefers-reduced-motion`。
- 不要让颜色成为唯一信息通道。
- 移动端 375px 下不能横向滚动。
- 表格在移动端必须横向滚动或转换为卡片。
- 图表必须有文字摘要或数据表 fallback。

## 9. 体验分层

默认支持两种阅读层级：

- 小白模式：只看结论、风险、建议。
- 专业模式：展开信号、回测、证据、参数。

切换规则：

- 默认进入小白模式。
- 专业模式要保留，但不能把新手界面变乱。

## 10. 验收标准

前端交付前必须检查：

- 首页首屏能看懂。
- 风险等级清楚。
- 推荐动作可执行。
- 订单草案不会误触。
- 图表不会遮挡文字。
- 小屏没有横向滚动。
- 深色模式不刺眼。
- 浅色模式不发虚。
- 图表和表格都可操作。

## 11. 关键决策

- UI/UX 目标是专业金融工作台，不是宣传页。
- 深色工作台为主，浅色阅读模式可选。
- 蓝色不是唯一主色，风险、盈利、警示必须分层。
- 所有关键动作都要可解释、可追溯、可确认。
- `ui-ux-pro-max` 是检索和设计规则来源，不是无条件生成器。
- 自动生成的页面级设计必须经过金融安全和操作确认原则筛选。
